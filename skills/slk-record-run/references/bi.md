# 通用 BI：直接使用成品

BI 是独立工具，不要求换成另一系列 SLK。使用已安装的 `slk-bi-desktop.exe`（本版配套 BI 1.1.6 或兼容新版）；没有时取官方 `DWG7318/slk-bi` 对应发布的 Windows 预编译包。启动原 exe，不编译，不加后台组件。此能力同样适用于仍使用 3.0.9 的 Supervisor。

## 登记与读取

由创建 Supervisor 在自身原生对话环境中执行一次登记：

```text
slk-bi.ps1 --bi-register "<工作簿绝对路径>" --project-id "<准确项目ID>" --project-name "<项目名>"
slk-bi.ps1 --bi-read "<RUN-ID>"
```

BI 读取原工作簿的 Run 定义、唯一当前摘要、成员、计划与结项总结；不读取 Agent 私有对话或把全本历史送给 WebBI。设备署名由执行 Agent 写入原工作簿，BI 不探测电脑名、IP地址或操作系统版本，缺失按未知显示。

新工作簿保留创建 Supervisor 的实际平台与原生任务 ID；更换成员不改创建者。CLI 通过已支持宿主的可信身份核对原创建者，不接收可随意填写的通用身份或 `--supervisor` 参数。不要伪造环境变量冒充其他成员。实际平台没有可信身份适配或原生消息/归档能力时如实说明；保留可用只读来源及未完成事项，不借同名或文字声明取得归档权限。宿主适配属于独立 BI，不在方法中新增鉴权系统。

当前摘要写真实状态、当前责任、更新时间和 D1 通过数/有效 CELL 总数；不以 TOKEN 归属冒充在线。计划可用 `CELL | 目标 | 状态 | 次数` 表（状态为 planned、working、d1_passed、d1_failed、split、exempt 或 unknown）；该表只是原计划的形式，不再复制第二份计划。成员表可增加 Agent、模型、推理列。拆分初始数与净增加数只有明确记录时才显示，不从总数差推测。

## 收尾与归档

按 `$slk-finalize-run` 完成相应方法收尾。先在原工作簿保存结项总结、唯一当前摘要和实际最终状态：完成为 `CLOSED`，废止为 `ABANDONED`。再由原创建 Supervisor 在自身可信宿主执行，核对读取结果包含刚保存的总结和状态后才归档：

```text
slk-bi.ps1 --bi-read "<RUN-ID>"
slk-bi.ps1 --bi-archive "<RUN-ID>"
```

使用现场准确 Run ID，并读取归档返回结果确认；已确认归档则跳过，不为重试覆盖快照。BI 保存只读来源的归档快照和创建者身份，保留历史；源仍未收尾会明确拒绝，不代写 D2 PASS 或 CLOSED。更换归属需 Owner 另行决定并保留原创建事实，不能静默重登记。

方法收尾、BI 本地归档和云端保存是不同事实，分别核验。断网留下待上传，不把本地成功称为 WebBI 已保存，也不重开工程。以后发现遗漏，由原作者在原工作簿追加更正，保留实际身份、时间和来源；不覆盖原归档快照、不改写历史 D2 或重开 Run，更正是否已被 BI 读取/云端保存仍按真实结果报告。

桌面按原刷新周期读取和上传，WebBI 不直连工作簿。来源缺字段显示未提供，来源格式不明确时报错；BI 不从自由文字生成正式消息类型或 ntfy 通知。读取失败先核对登记路径/当前摘要，交回 Supervisor 现场处置，不加工程开工门槛。
