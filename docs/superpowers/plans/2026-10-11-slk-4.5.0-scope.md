# SLK 4.5.0 范围记录

日期：2026-10-11（北京时间）。状态：Owner 已要求以 goal 先完成 OW 升级，再依次完成 P、S、M；全部验收后合并 main、push GitHub、部署本机并安全清理旧版，最后通知准确的 Supervisor 用 4.5.0 开始 run07。不是实现或验收完成声明。

## 前置版本

4.4.5 完成已有必要修复并验收后关闭；4.5.0 以修复后的版本为基线，不承接未完成维修任务。本记录不改源码版本、真实 Run、安装环境或发布状态。

## 已确认范围

- Owner 更新（2026-10-11，北京时间）：本轮所有 Skill 的逐份确认委托主维护者，不再等待 Owner 人工逐项批准；保持逐份语义核查和验证，不改变未来 Run 的 Supervisor、模型及业务权限确认。

- 轻量准备：每次只确认完整 SLK/Skill、DSH/OCRV 等必要组件、成员真实身份与端点、BI 可用及共享 Temporal/本 Run 工作流就绪；不要求每个 Run 重跑完整流程验收。
- OW 归属调整（Owner 2026-10-11 最新决定）：三个主体角色为 Supervisor、Checker、Worker；OW 不再是并列的独立角色，而是 Supervisor 启动的唯一直属 subagent，必须采用高效、低推理开销且能完成真实性核查的模型。`gpt-6-luna`、`high` 或 `xhigh` 只是 Owner 推荐，不强制型号、系列或档位，也不据此设置开工门槛。同一 Supervisor 的全部 Run 由这一个 OW 覆盖，不按 Run 重建 OW，也不与其他 Supervisor 共用；以真实 Supervisor 实例/原生定位辨别归属，不能用每 Run 的不同 role instance 或名称代替。
- 简化目的：OW 与 Supervisor 优先使用宿主原生父子通讯，使异常尽快直达所属主管并由其介入，不再要求 OW 独立跨会话寻址、补救投递或套用工程交接/ACK/TOKEN。OW 只观察、不干预：核验真实情况、记录自身观察并向所属 Supervisor 报告；疑似异常同样只报，不派工、不代发工程交接、不重试或修复、不改 BI/TOKEN/施工状态，也不借用父级工程权限。原生消息受理不冒充 Supervisor 已读、已介入或已解决；创建 subagent 也不保证 Supervisor 永不断连，真实失活仍由现有 Temporal 保障处理，不加另一层机制。
- 角色理解过程保留并轻量化（Owner 2026-10-11 补充）：不只保留 Eval，还保留角色定位说明、必要规则学习、理解确认、误解纠正与纠正后确认；让成员明确自身职责/禁区及真实交接对象和入口。复用精简角色指引及现有 Eval/等价验证，合并重复动作；普通 CELL 切换不重复，变化只重确认受影响内容，不扩大为全文背诵、重复考试或工程演练，整个过程纳入轻量准备时间。
- 正式交接必须是角色本次工作激活的最后一个任务动作：先完成工作与必要记录并停止相关业务活动，再完成既有真实交接，成功后结束本次激活；不交接后继续干活。未闭合只恢复原交接，不重跑/重发。OW 异常汇报不等于工作交接，不因此停止持续巡查或影响其他 Run。
- 效率建议不是时间门槛（Owner 最新澄清）：基本检查约 10 分钟、常见缺项配置约 10 分钟仅作体验参考，不设总时长上限、到时中断、自动失败或统一子进程超时，也不作准入/验收条件。是否就绪看必要条件与真实结果，耗时仅用于优化，真实故障如实报告。
- 真实故障与正常准备分开记录：修复耗时较长不等于预检必须再加重，也不因超过建议时长强停；保留已完成项，修复后只复核受影响部分，不反复从头准备。
- 两个独立排障子 Skill（Owner 最新澄清，名称暂定、正文分别确认）：`slk-troubleshoot-preflight` 处理开工/重新准备中的组件、配置、登记、理解和就绪问题；`slk-troubleshoot-run` 处理正式施工中的成员、通讯、交接、状态、资源及保障异常，保护已有成果并从可信状态恢复。不再设置一个通用排障 Skill。
- 排障预案按需提供开发阶段编写/验证的线索、取证命令、最小修复建议及验证/回退；保留 `slk-recover-communication` 作为已有精确投递/交接的具体恢复规程，两个排障 Skill 负责定位并推荐入口，不复制重试/回读/ACK/TOKEN 操作。无已有投递的准备缺项沿团队准备入口纠正；已明确通讯故障可直接恢复，不加必经排障层。原责任角色执行、Supervisor 决策、OW 不代发的边界不变；允许新问题与不同根因，正常 D1 FAIL 不改判，修复经验验证后再维护，不把猜测推广为全局限制。
- 成品交付：开发/发布阶段准备并验证 BI、状态/查询工具、传输包、DSH/OCRV 依赖与适配器、Temporal 配套依赖/模板、探针和默认配置；使用者调用现有安装入口，不现场编译或反复组装。
- 一键部署：安装包已下载、凭据可用的正常目标环境，追求快速完成部署并打开 BI，约一分钟仅作体验参考而非硬限制。下载等外部耗时单独如实显示，缺失成品不自动退回源码构建。
- 本机与 Run 变量仍现场绑定：凭据、设备路径、成员 Session/端点、Run 身份及 Owner 选择的参数不预造、不锁死，也不随公共包传播。
- 主/子 Skill 重构（Owner 2026-10-11 补充）：17 个只是现状，不是目标或上限；按独立职责与触发时机合理新增、拆分，不能遗留大型 Skill。主 Skill 保留最小总则、角色边界与导航，子 Skill 短而聚焦，技术细节按需读取，同一规则只有一个权威出处。
- 拆分不转嫁负担：不以必读巨型附件或要求整套子 Skill 全文加载伪装精简，也不碎片化成空壳路由；同步入口、安装和集合验证，不增加角色、审批层、TOKEN 节点或交接次数。用保留的角色理解确认、Eval 和情境验证检查必要指引是否足够，不以删掉角色理解动作换取缩减数字。
- 去重去繁不偷改语义：除 Owner 已明确批准的轻量准备和 OW 直属 subagent 调整外，保留主体角色、通讯责任、D0/D1/D2、TOKEN、权限与真实证据边界；其他整理逐条核对旧规则归属，不以删行数或单文件硬上限作为完成标准。
- 三步顺序（Owner 2026-10-11 补充）：先轻量预检，开始前提交详细计划；再重构/精简 Skills，每份现有、新增或拆分 Skill 分别确认后采用；最后工具模块化，由维护方自主施工。第一步仅同步必要预检条款，不借机全面改写 Skills。
- 工具 Git/subtree：每个实际工具有独立 Git，已有库沿用，新建工具库从 `1.0.0` 首发；已有产品版本/历史不因拆库倒退。源码、构建规则和经过验证的成品一起纳入主库 subtree，明确关联 main 的工具 commit/tag/版本/hash，Release 分发不替代成品归档。
- 工具采用本次最新版：第三步以完成第一、二步后的 4.5.0 实际源码为准，修改过的工具重建成品，不沿用旧缓存；不在开工时浮动更新或现场编译。
- OW 模块化：`slk-overwatch-run` 指导 Supervisor 的唯一 OW subagent；配套工具独立维护/打包（库名 `slk-overwatch-tools`，已有独立库则沿用），不另造独立 OW Agent、调度器或常驻服务。登记/BI 保留 OW 的真实原生身份、所属 Supervisor、模型和状态；subagent 不继承 Supervisor 的工程写权限。10 分钟主动核验、报告后继续、各 Run 独立取证、不写 BI/TOKEN/工程进度及退出二次确认不变；解除一个 Run 不停止仍看管其他 Run 的 OW，全部 Run 收尾后由所属 Supervisor 确认停止。Temporal 的独立核查和成员停留提醒继续保留；必须实测 Supervisor 暂时不生成时 OW 仍可持续工作，不能把创建成功或模拟回执冒充持续在线。
- 探针模块化：同一个 `slk-native-probe` 工具库内维护 DSH/OCRV 两种原生适配，与可选 Probe CLI 分开；先核实并补齐现有绑定式取证与全工具非归档 Session 采集的能力差距，不只搬目录改名。宿主内统一一分钟采样、headless、每工具采集持久化总计 10MB；原始日志/资料读取不受该预算限制，不复制私密正文，缺证/覆盖不足如实 UNKNOWN。归档只认原生标记，Run 关联依精确登记/native start，不以其他 Session 活跃替代。
- 探针一键部署与 BI 同入口：部署已验证插件/读取器和必要依赖、核对实际宿主位置，不要求手改代码或现场编译；一次安装不按 Run 重装、不重复 hook/计时器，保留账号/模型/Session 数据，失败可回滚，需宿主加载时不假记成功。第一步先闭合现有成品部署，第三步完成模块化后重新生成最新版统一包；源码/成品经独立 Git 与 subtree 留存。
- subagent 已获允许：可做明确分工的盘点、开发和验证，不新增 SLK 正式角色、按 Owner 委托由主维护者确认 Skill、不自动触碰真实在途 Run。

详细计划：[三步升级计划](2026-10-11-slk-4.5.0-preflight-skills-plan.md)。共 12 个主开发任务（P1–P4、S1–S3、M1–M5）；OW 源码升级、P1 安装/runtime/配置与 Git 闭包、P2 普通预检减重已通过独立复核。P3 主 Skill 与七份相关子 Skill 的必要替换提案由主维护者按最新委托逐份核实采用，独立SPEC/QUALITY已通过。P4 实际中间包安装、成品调用与 BI 数据加载已留证，PS5.1 headless 中文输出小修已独立复核通过；最终450包随M完成后重建验证。S的21份正文已逐份审查采用，17组独立指引情境及150项集合/Eval测试通过；独立SPEC/QUALITY均已APPROVE，QUALITY连同D2单行版本继承修复共232项测试通过、43份审查文件哈希前后一致，主维护者据此接受S。M1盘点已接受，M2/M3/M4开始实现，具体边界见[工具模块化决定](2026-10-11-slk-4.5.0-tool-modules.md)。正式 Skill 仍逐份核查，不再等待 Owner 人工审批。最终清理仅限已核实废弃的旧版程序/安装资产，保留账号、配置、Session、Run 与回退材料；安装后读回实际加载版本，完成前不打扰在途 Supervisor，通知 run07 不等于其已接收或开工。
