# SLK 4.0 Resource Continuity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task by task.

**Goal:** Add a small, reusable resource-continuity guard to SLK so Cargo lock/contention incidents do not silently break the Loop, while keeping the method prompt concise and preserving all current roles, TOKEN semantics, CELL planning, D0/D1/D2, and rework behavior.

**Architecture:** Add one compact SLK child skill that performs a static pre-run resource check and routes Cargo work through a Rust CLI. The CLI gives each SLK Run an isolated target directory, streams the original command output, classifies only explicit contention evidence, performs at most one bounded recovery retry, emits existing resource state events when credentials are available, and safely cleans only its own Run runtime. Existing Worker and Checker guidance continues to share the current resource-contention reference.

**Tech Stack:** Rust 2021 workspace, `slk-state-core`, Cargo integration tests, Python repository/skill validators, Markdown skills.

---

## Scope invariants

- Keep Supervisor, Checker, Worker, GO, CELL, D0, D1, D2, rework, SLK TOKEN, and communication topology unchanged.
- Add no polling, patrol, daemon, extra role, extra inspection layer, or resource-management CELL.
- Treat Cargo as the named historical case. Ask only one generic question for other obvious exclusive resources.
- Keep operational detail out of shared skill prompts; place it in CLI help, code, and tests.
- Do not make `slk-cargo` a prerequisite for unrelated SLK work. If a planned Run does not use Cargo, resource planning ends after the static check.
- Do not merge, push, tag, or release as part of this plan.
