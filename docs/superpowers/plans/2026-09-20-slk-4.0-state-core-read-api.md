# SLK 4.0 State Core and Agent Read API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a machine-wide, role-authored SQLite state core, deterministic Markdown export, and read-only Agent query CLI behind the accepted SLK cross-Agent transport.

**Architecture:** A Rust workspace provides one reusable `slk-state-core` library plus two short-lived CLIs: `slk-state` for authenticated writes by Supervisor, Checker, and Worker, and `slk-bi-query` for read-only JSON queries. SQLite is opened only for each command, uses WAL/foreign keys/transactions/bounded busy retry, and stores structured facts while durable evidence remains under the selected `SLK_DATA_ROOT`. Transport remains separate: a sender records a TOKEN handoff only after `slk-transport` proves native start, and a receiver records `WORK_STARTED` as the first act of its real assignment.

**Tech Stack:** Rust 2021, `rusqlite` with bundled SQLite, `serde`/`serde_json`, `uuid`, `sha2`, `thiserror`, `directories`; Python pytest only for repository-level compatibility assertions.

---

## File structure

- `Cargo.toml`: workspace containing the state library and two CLIs.
- `crates/slk-state-core/src/config.rs`: machine-wide root selection and safe path resolution.
- `crates/slk-state-core/src/schema.rs`: schema versioning, migration backup, WAL and invariants.
- `crates/slk-state-core/src/model.rs`: closed command, event, identity, and query types.
- `crates/slk-state-core/src/auth.rs`: Run-scoped role credential hashing and authorization.
- `crates/slk-state-core/src/write.rs`: transactional role-authored commands and TOKEN transitions.
- `crates/slk-state-core/src/query.rs`: stable read projections shared by CLI and future BI.
- `crates/slk-state-core/src/export.rs`: deterministic `SLK-RUN-<RUN-ID>.md` generation.
- `crates/slk-state-core/src/evidence.rs`: durable evidence copy, identity, and hash verification.
- `crates/slk-state-core/src/resource.rs`: generic contention classification and bounded recovery facts, including Cargo isolation guidance.
- `crates/slk-state-core/migrations/0001.sql`: initial schema and append-only triggers.
- `crates/slk-state-cli/src/main.rs`: `configure`, `init-run`, `write`, `export`, and `verify-evidence` commands.
- `crates/slk-bi-query/src/main.rs`: read-only JSON commands with no credential or mutation path.
- `tests/state/`: repository-facing tests for CLI binaries, permissions, concurrency, export, and transport boundary.
