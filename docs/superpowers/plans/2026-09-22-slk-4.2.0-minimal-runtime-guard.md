# SLK 4.2.0 Minimal Runtime Guard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. This Owner requested inline execution; do not create subagents.

**Goal:** Ship SLK 4.2.0 with mechanical role understanding, atomic successor lifecycle, bounded Codex busy recovery, truthful BI lineage/activity language, Windows headless subprocesses, and optional RTK/Probe guidance.

**Architecture:** Extend the existing SQLite core and detached transport job instead of adding a service. One data-driven Python Eval validates role decisions; one schema migration stores explicit lineage; the current Codex adapter retries only the frozen thread within its existing startup deadline; BI remains read-only.

**Tech Stack:** Rust/rusqlite, Python standard library/pytest, React/TypeScript/Vitest, Tauri 2, SQLite migrations.
