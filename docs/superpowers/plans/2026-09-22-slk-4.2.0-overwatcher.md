# SLK 4.2.0 Optional Overwatcher Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans and superpowers:test-driven-development task by task. This Owner requested inline execution; do not create subagents or new Codex tasks.

**Goal:** Ship SLK 4.2.0 with fixed Codex/OCRV/DSH role bindings, explicit D1 PASS/FAIL/INCOMPLETE semantics, one closed D1-failure rework route, an optional one-per-Run Overwatcher, evidence-based communication recovery, truthful TOKEN/BI projection, lightweight interpretation Eval, and headless Windows helpers.

**Architecture:** Extend the existing Rust SQLite authority with a small Overwatcher binding and append-only operational observations. Reuse the current immutable transport envelopes and exact endpoints for idempotent retry, and keep LE BI as a read-only projection. Replace the aborted mandatory Router implementation rather than adding another runtime.

**Tech Stack:** Rust/rusqlite, Python standard library/pytest, React/TypeScript/Vitest, Tauri 2, SQLite migrations.

  run_id TEXT PRIMARY KEY REFERENCES runs(run_id),
  role_instance_id TEXT NOT NULL UNIQUE,
  session_id TEXT NOT NULL UNIQUE,
  endpoint_version INTEGER NOT NULL CHECK (endpoint_version > 0),

  related_event_id TEXT,

  plan_revision INTEGER NOT NULL CHECK (plan_revision > 0),
  evidence_refs_json TEXT NOT NULL,
  details_json TEXT NOT NULL,
  payload_sha256 TEXT NOT NULL,
