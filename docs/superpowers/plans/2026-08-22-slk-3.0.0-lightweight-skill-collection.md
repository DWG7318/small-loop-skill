# SLK 3.0.0 Lightweight Skill Collection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. This execution stays in the current primary conversation; formal SLK member topology is not used to build SLK itself.

**Goal:** Replace the SLK 2.6.0 monolith with one lightweight router Skill and twelve situational sibling Skills while preserving the Owner-approved SLK core.

**Architecture:** The repository exposes the active collection under `skills/`. `skills/small-loop-skill` defines identity and routing; twelve sibling folders provide short, situation-specific guidance. The active runtime surface contains no 2.x Control/Verifier/Patrol contracts. Repository tests validate collection identity, routing, role ownership, progressive disclosure, manifest integrity, and absence of legacy active concepts.

**Tech Stack:** Markdown Skill packages, Python 3.12 repository validator/tests, GitHub Actions on Windows and Ubuntu.

---

## File map

### Active collection

- `skills/small-loop-skill/SKILL.md`: SLK identity and state router.
- `skills/small-loop-skill/agents/openai.yaml`: concise UI metadata for the main Skill.
- `skills/slk-plan-run/SKILL.md`: Run/GO/CELL, Agent-derived lean checks, and per-CELL capability planning.
- `skills/slk-select-models/SKILL.md`: situational capability selection for Supervisor, Checker and Worker.
- `skills/slk-grill-supervisor/SKILL.md`: one-question-at-a-time Supervisor understanding check.
- `skills/slk-manage-team/SKILL.md`: visible member creation, recovery, communication tests and archive.
- `skills/slk-dispatch-cell/SKILL.md`: pre-dispatch reality check and Checker-to-Worker CELL handoff.
- `skills/slk-execute-cell/SKILL.md`: Worker execution, minimum D0 and delivery.
- `skills/slk-check-cell/SKILL.md`: isolated Checker D1.
- `skills/slk-record-run/SKILL.md`: shared engineering record guidance.
- `skills/slk-record-run/assets/SLK-RUN.template.md`: readable root record starter.
- `skills/slk-rework-cell/SKILL.md`: ordinary D1 rework.
- `skills/slk-adjust-run/SKILL.md`: event-activated Supervisor decisions on capability, environment, route or exemption.
- `skills/slk-recover-communication/SKILL.md`: message activation and member communication recovery.
- `skills/slk-close-run/SKILL.md`: D2, return-to-work route, archive and Owner conclusion.

### Repository governance

- `tests/skill_testkit.py`: frontmatter and advisory-language helpers.
- `tests/test_skill_collection_300.py`: core, child, routing and legacy-removal tests.
- `tests/test_repository_300.py`: version, manifest, CI and documentation tests.
- `scripts/validate_repository.py`: compact collection and manifest validator.
- `README.md`, `README.zh-CN.md`: human entrypoints.
- `MIGRATION.md`, `CHANGELOG.md`, `VALIDATION-REPORT.md`, `VERSION`, `MANIFEST.json`: release carriers.
- `.github/workflows/validate.yml`: cross-platform validation.

### Retired active surface

The 2.6.0 tag and Release remain the recovery source. After 3.0 tests cover the new collection, remove the active 2.x root/mirror contracts, templates, runtime validators, examples and tests so they do not compete with the new method.
