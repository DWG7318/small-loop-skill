# SLK 4.0 Cross-Agent Transport Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and prove exact, bidirectional activation between one Codex Supervisor Agent, one OCRV Checker Agent, and one DSH Worker Agent before SLK 4.0 state storage or BI work begins.

**Architecture:** Add a standard-library Python transport package that accepts a closed SLK envelope plus an exact role endpoint and delegates to one of three native runtime adapters. A transport attempt runs as a short-lived per-message job, produces immutable evidence, and exits; it is not a fourth Agent, workflow authority, state database, message queue, or resident relay. The live acceptance drill uses disposable repositories and exact runtime/session identities to prove `Supervisor -> Checker -> Worker -> Checker -> Supervisor`, failure retention, session rebound, and two-Run isolation without changing a user project.

**Tech Stack:** Python 3.10+ standard library, pytest, JSON/JSONL, subprocess, Codex App Server JSON-RPC, DSH headless/resume CLI, OCRV SLK Checker adapter, Git disposable repositories.

- [ ] **Step 3: Implement adapter protocol and dispatcher**

```python
class Adapter(Protocol):
    def deliver(self, endpoint: Endpoint, envelope: Envelope, attempt: Attempt) -> DeliveryResult: ...


ADAPTERS: dict[str, type[Adapter]] = {
    "codex-app-server": CodexAdapter,
    "ocrv-checker": OcrvAdapter,
    "dsh-worker": DshAdapter,
}
```

Unit tests pass an explicit test-only adapter mapping to `dispatch_once`; `fake` is never accepted by the production endpoint contract or CLI.

`dispatch_once` validates endpoint and envelope before it creates an attempt. It writes `accepted.json` only after adapter selection and address validation, writes `started.json` only after native runtime evidence proves the target job began, and writes one terminal result. No retry advances or changes `token_sequence`; a retry reuses the same message ID, endpoint version, and payload hash.

The CLI has exact commands:

```text
slk-transport validate --endpoint endpoint.json --envelope envelope.json
slk-transport send --endpoint endpoint.json --envelope envelope.json --attempt-root <path>
slk-transport job --endpoint endpoint.json --envelope envelope.json --attempt-root <path>
slk-transport drill --config drill.json --evidence-root <path>
slk-transport drill-verify --evidence-root <path>
```

`send` starts one detached `job` process on Windows, waits only for `started.json`, `failed.json`, or a bounded startup timeout, prints a one-line JSON result, then exits. The `job` process remains only for that delivery and exits at its terminal result. No listener, port, polling daemon, or queue is created.
