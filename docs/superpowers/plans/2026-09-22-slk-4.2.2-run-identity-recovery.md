# SLK 4.2.2 Run Identity Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. This Owner-approved execution stays in the current SLK owner session; do not create subagents or new tasks.

**Goal:** Add two narrow, Owner-evidenced state operations that converge explicitly named historical Run identities and adopt the 4.2.2 method contract without rewriting engineering history or moving TOKEN.

**Architecture:** Schema v6 preserves the origin version and stores two append-only administration receipts. The canonical Run's Supervisor supplies closed Owner evidence and exact optimistic snapshots; one immediate transaction validates every fact, performs the bounded metadata update, and records the immutable receipt. Query/BI only honor cross-root convergence when a matching receipt exists.

**Tech Stack:** Rust 2024, rusqlite/SQLite, serde JSON, Python pytest/optimized validation, React/TypeScript BI contracts, Markdown Skills.
