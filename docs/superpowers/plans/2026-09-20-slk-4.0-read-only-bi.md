# SLK 4.0 Read-Only BI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and accept a standalone, read-only SLK desktop BI that presents the existing machine-wide state authority and remains suitable for future LCaS embedding.

**Architecture:** A compact React 19/Vite frontend runs in a minimal Tauri 2 shell. Tauri commands call `slk-state-core` query functions directly and open SQLite read-only per request; the frontend owns only selection, filtering, refresh, and theme state. The existing `slk-bi-query` CLI remains the Agent read API, and parity tests keep CLI and desktop projections identical.

**Tech Stack:** Rust 2021, Tauri 2, React 19, TypeScript 5.8, Vite 6, Vitest 3, Testing Library, plain CSS tokens compatible with the LCaS workbench language.
