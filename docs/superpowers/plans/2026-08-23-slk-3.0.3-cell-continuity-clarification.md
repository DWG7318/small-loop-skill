# SLK 3.0.3 CELL Continuity Clarification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Do not use subagents unless the Owner separately authorizes them. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the ambiguity that lets a Checker dispatch one planned CELL as a sequence of one-command activations or lets a Worker treat an intermediate command result as CELL completion.

**Architecture:** Preserve the complete SLK 3.0 role topology, Loop, D0/D1/D2, message activation, and no-`wait_threads` behavior. Change only the existing dispatch and execution wording, keep their physical line counts unchanged, and lock the intended behavior in the existing semantic tests.

**Tech Stack:** Markdown Agent Skills, Python 3 repository validation, JSON SHA-256 manifest, pytest.

---

## Fixed behavior

One Checker dispatch contains one complete planned CELL. The Worker receives that CELL once and continues through the edits, tool calls, commands, tests, and minimum D0 reasonably required to produce the whole candidate. A command, tool result, intermediate observation, or local progress note is not a delivery, CELL boundary, or reason for the Worker to end its current activation.

The Worker ends its current CELL work only by:

```text
complete candidate delivery
real blocker that prevents continued construction
necessary clarification that the Checker must answer before construction can continue
```

This clarification does not authorize Checker monitoring, Worker `wait_threads`, command-by-command dispatch, a new role, a new Skill, or extra validation layers.
