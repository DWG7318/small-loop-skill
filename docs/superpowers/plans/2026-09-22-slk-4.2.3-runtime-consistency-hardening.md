# SLK 4.2.3 Runtime Consistency Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Owner requires inline execution in this existing SLK owner task; do not create subagents or new Codex tasks.

**Goal:** Ship and locally install SLK 4.2.3 with early native start evidence, atomic delivery-start state, state-aware Supervisor recovery, bounded Worker task/workspace identity, and mechanically enforced whole-Run Overwatcher continuity.

**Architecture:** Extend the existing Python transport and Rust state core rather than adding a coordinator. Transport creates immutable task/start/recovery evidence; state schema v7 commits start receipt, TOKEN, work event, and one read snapshot in a single transaction. Overwatcher liveness/cadence/incidents use append-only facts, and a staged package installer replaces all global surfaces or rolls them all back.

**Tech Stack:** Python 3.10+, pytest, Rust 2021/rusqlite/SQLite, React/TypeScript/Vitest, PowerShell 7, Codex App Server JSON-RPC.
