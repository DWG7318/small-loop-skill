# SLK 5.0.0 Router Control Implementation Plan

**Goal:** Replace peer-driven TOKEN/handoff control with one deterministic Router role while preserving Supervisor decisions, Checker D1, Worker D0, serial CELL semantics, read-only BI, and lightweight local operation.

**Architecture:** Add a Router identity and schema-v4 result/transition ledger to the existing Rust state core. Add a small headless Python runner that applies only the core's closed next-action decisions and existing exact-endpoint transport. Keep one SQLite authority and reuse the current BI projection.

## 1. Freeze topology contracts with RED tests

- Add Rust/Python repository tests for exactly four roles, separate Router identity/credential, `SUPERVISOR_HOSTED` binding, and forbidden cross-role authorship.
- Add negative prompt/Eval cases for the observed Supervisor wait/over-participation and direct Checker/Worker routing errors.
- Add state tests proving ordinary roles can submit results but cannot move TOKEN or project state.

## 2. Add schema-v4 Router state

- Add Router to the role model and initialize one compatibility Router beside Supervisor.
- Add immutable `role_results`, idempotent `router_transitions`, and one-per-Run `router_runtime` lease/binding record.
- Keep legacy 4.x records readable; backfill nothing into fake Router facts.
- Add explicit successor lineage and atomic lifecycle transition so corrective predecessors leave the active BI set.

## 3. Implement the closed transition engine

- Validate and store Supervisor/Checker/Worker results with exact scope, attempt, producer, plan revision, payload hash, and evidence references.
- Compute next actions from an exhaustive enum/table, not free text.
- Prepare, fail, resume, and commit a transition idempotently; consume each source result once.
- Require Router credential plus matching native start proof for TOKEN commit.
- Route ambiguous, invalid, blocked, timeout, replacement, exemption, and plan-change cases to Supervisor without manufacturing a decision.

## 4. Add the lightweight headless Router runner

- Add `slk-router start|run|step|status|stop` within the existing Python package and no third-party runtime dependency.
- Enforce one Run lease, durable resume, bounded deadlines, exact endpoint use, and terminal shutdown.
- Reuse transport adapters; never use `wait_threads`, poll conversation text, guess task IDs, or create roles.
- Apply one shared Windows no-window launch policy to Router, detached jobs, Codex, DSH, and OCRV.

## 5. Correct BI and Run lifecycle projection

- Project Router expected actor/action and last confirmed transition without exposing a write surface.
- Show only open Runs as active; keep explicit predecessors in archive/history and preserve unrelated independent Runs.
- Replace stale “working” language with confirmed/start-unconfirmed/stalled/blocked facts.
- Reproduce the reported five-LCaS-card scenario with explicit successor and independent-run fixtures.

## 6. Replace method wording and add the four-role Eval

- Replace, rather than append to, the main Skill and companion-role communication text.
- Add one compact closed Eval pack/validator for Supervisor, Router, Checker, and Worker, including identity variants and `python -O` negatives.
- Update README, state/transport docs, migration, changelog, templates, version, manifest, and validation report without duplicating the transition table across files.

## 7. Verify and package the local candidate

- Run focused RED/GREEN tests after each layer, then full Python, optimized Python, Rust workspace, BI test/typecheck/build, repository validator, migrations, mirrors, manifest/hash, sensitive/role-boundary scans, and full base-to-HEAD `git diff --check`.
- Commit locally on `feature/slk-5.0.0-router-control`, keep the worktree clean, and do not push, merge, tag, release, or alter the original dirty checkout.
