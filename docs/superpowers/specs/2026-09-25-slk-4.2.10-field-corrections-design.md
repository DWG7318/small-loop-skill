# SLK 4.2.10 Field Corrections Design

## Scope

This patch corrects the closed LCaS RC08 field findings without changing the three engineering roles, CELL/D0/D1/D2 authority, direct communication routes, optional whole-Run Overwatcher, TOKEN ownership, model bindings, or BoM-disabled policy.

## Chosen approach

Use a prompt-first hybrid:

- Replace ambiguous Skill wording and add negative role-Eval cases for delayed self-wake, time promises, Worker completion suffix, Checker evidence discipline, low-severity findings, Overwatcher exits, and Cargo command-session reuse.
- Extend only existing deterministic transport helpers where the failure crosses Agent/process boundaries: active-writer recovery, resumed DSH identity, DPAPI decoding, JSON command outcomes, recovery revision propagation, slim evidence indexing, and independent headless OCRV launch.
- Project existing authoritative Overwatcher records into LE BI. BI remains read-only and never infers work from role lifecycle alone.

Prompt-only correction was rejected because exact message identity, byte decoding, process exit/JSON status, revision binding, and BI projection must be mechanical. A scheduler, heartbeat, daemon, post-turn script, Temporal-like controller, or new state machine was rejected because it would invent continuity the platform does not provide and make SLK heavier.

## Behavioral contract

1. No critical handoff may depend on a delayed script, background process, self-wake, or promise to resume after a number of seconds. If the canonical Codex task has an active writer, preserve the failed attempt and send one new payload-hash-bound recovery message to that exact task/turn. If no verified continuation route exists, wait for an actual Owner/Main activation and say so truthfully.
2. Worker completion remains `result -> D0/CANDIDATE_SUBMITTED -> one Worker-to-Checker handoff`. A resumed DSH process must receive and verify its frozen instance/session identity. OCRV review starts headless and outside the DSH Job Object when invoked from a resumed DSH process.
3. DPAPI plaintext accepts strict UTF-8 or UTF-16LE (BOM or supported alternating-NUL form), strips at most one terminal NUL character, rejects embedded NULs, and validates the closed credential shape.
4. JSON command handling keeps process exit, parse status, and business status distinct. Valid JSON on stdout remains available for nonzero business outcomes such as `INCOMPLETE` or `FAIL`; malformed/no JSON remains a tool failure.
5. Recovery writes and delivery commits return the resulting runtime revision. The next mutation must use that returned/fresh revision rather than a stale pre-recovery value.
6. Checker receives a small evidence index by default; raw logs remain hash/path-addressable. Checker may serially inspect multiple dimensions inside one D1 and emits one final PASS/FAIL/INCOMPLETE. Complete coverage with only low observations is not mechanically converted to FAIL.
7. An Overwatcher turn has exactly three exits: record a normal cycle and continue; report one anomaly then pause; or record the terminal cycle, close, and archive. LE BI shows binding lifecycle, latest native status, latest valid cycle time, anomaly pause, and terminal close as separate read-only facts.
8. Cargo-heavy D2 planning consolidates compatible filters in one safe command session when sandbox SID differences would force repeated relinks. It never bypasses the resource guard or creates a resident cache service.

## Compatibility and non-goals

SLK 4.2.10 is a schema-v8-compatible patch. Existing 4.2.9 Runs keep roles, plan, TOKEN, candidates, evidence, Overwatcher identity, and engineering history. No product repository is modified. DeepSeek V4 Flash remains the Worker; Pro is not introduced. BoM stays disabled.

## Acceptance

- Negative Skill/Eval tests reject delayed self-wake, fixed-time promises, low-finding-as-FAIL, Overwatcher spinning after anomaly, OCRV-in-DSH hosting, BoM, and Worker Pro substitution.
- Active-writer recovery supports exact Checker-to-Supervisor handoffs, preserves the failed message, creates one new recovery identity, and never blindly replays.
- UTF-16LE/BOM credentials pass; pseudo-UTF-8 with embedded NUL and malformed terminators fail closed.
- Nonzero valid stdout JSON preserves its business outcome and tri-state metadata.
- Worker recovery returns the committed runtime revision and a slim hash-bound evidence index.
- LE BI distinguishes central binding, native liveness, last cycle, paused anomaly, and closed state.
- Focused tests, full Rust/Python/UI tests, `python -O` negatives, repository/Manifest/package/install verification, diff check, and local deployed identity all pass.
