# SLK 4.2.5 Authenticated Checker Recovery Design

## Problem

SLK 4.2.4 can identify a terminal DSH Worker whose D0/candidate/Checker handoff suffix is missing, but its public `resume-worker-continuation` command does not prove that the original OCRV Checker initiated recovery. A Supervisor can therefore invoke a command that the method assigns to Checker. Separately, an `active` Overwatcher projection can outlive the foreground turn that was supposed to produce 180–300 second cycles.

## Minimal boundary

1. Supervisor sends one closed `WORKER_COMPLETION_RECOVERY` envelope to the exact registered Checker endpoint. It cannot invoke the Worker continuation command directly.
2. The OCRV adapter derives a deterministic invocation ID from that envelope, records an early native `started.json` as authentication pending and unauthorized, and starts the same registered OCRV command with a narrow recovery flag.
3. The repository-supplied OCRV companion strips inherited role secrets and invokes the internal `checker-recover-worker` command. That command accepts only the exact native OCRV invocation markers, authenticates the Checker credential against the current Run/revision, and only then resumes the exact DSH instance/session. Only the final closed result may state `checker_authenticated=true` and `authorized_recovery=true`.
4. OCRV integration installs only the wrapper and recovery companion after backing up the accepted wrapper. Installation and rollback require an explicit OCRV root, verify bytes, and never install dependencies or alter the accepted D1 adapter.
5. `inspect-overwatcher-cadence` reads one Run projection and observation time. A projected active role without current cycles is `CONTINUITY_UNPROVEN`; one missed interval is `LATE` and wakes the same bound Overwatcher; more than two intervals returns to Supervisor review. It creates no heartbeat, timer, daemon, replacement, or state mutation.

## Compatibility

Existing 4.2.4 Runs retain their contract. Explicit `4.2.4 → 4.2.5` adoption preserves TOKEN, engineering history, plan, roles, and a proven active Overwatcher. The OCRV companion is installed separately from the global SLK package and may be rolled back to the exact saved wrapper.

## Non-goals

No new role, CELL, D0/D1/D2 rule, scheduler, resident service, automatic replacement, model change, product edit, R3B recovery, or live OCRV mutation is part of this candidate.
