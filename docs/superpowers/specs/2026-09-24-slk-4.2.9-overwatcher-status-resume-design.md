# SLK 4.2.9 Overwatcher Status-Basis Resume Design

**Date:** 2026-09-24
**Status:** Owner/Supervisor approved for implementation

## Problem

`record-overwatcher-status` records native `COMPLETED`, `MISSING`, or `MISMATCHED` evidence and changes the exact binding continuity to `VIOLATION`. A normal cycle and the current `resume-overwatcher-turn` both require `ACTIVE`, while resume also requires an exact last anomaly cycle. Once the native status is recorded first, the same Session cannot produce that cycle or resume; only replacement remains.

The R3B 4.2.8 closeout also showed two guidance gaps: the Skill used incident code `OVERWATCHER_CONTINUITY_VIOLATION` as though it were a cycle anomaly code, and terminal cycle guidance did not state the exact `native_active_session_evidence_ref` structure.

## Approved minimal contract

`resume-overwatcher-turn` accepts exactly one evidence basis:

- `last_anomaly_cycle_id`: the existing path, unchanged, while continuity is `ACTIVE`;
- `last_native_status_id`: the new path for the latest exact non-`IN_PROGRESS` status receipt while continuity is `VIOLATION`.

The status basis is available to effective 4.2.8 and 4.2.9 Runs so an existing 4.2.8 Run can recover before explicit adoption. It must match the current binding revision, role, Session, old foreground turn and latest native status receipt; the receipt liveness must be `COMPLETED`, `MISSING`, or `MISMATCHED`. The request also binds a fresh runtime revision, Supervisor credential, new foreground turn and hash-valid native active-session evidence. A replacement after the receipt makes the old receipt ineligible.

Success keeps the same role, Session and binding, updates only the foreground turn and active-session evidence, restores continuity to `ACTIVE`, appends `RESOLVED` to the existing incident, writes the existing `OVERWATCHER_TURN_RESUMED` event and advances runtime once. No ordinary cycle is accepted while continuity is `VIOLATION`; no state, role, scheduler or workflow layer is added.

## Anomaly code ownership

- `OVERWATCHER_CONTINUITY_VIOLATION` is an incident code produced by native status handling. It is not a member of `cycle.anomaly_codes`.
- `OVERWATCHER_ACTIVE_DEGRADED` is the cycle anomaly code when the binding remains `ACTIVE`, native liveness remains `IN_PROGRESS`, and the cycle's active-session check is anomalous.

The Skill and documentation state this mapping explicitly. The closed cycle enum is unchanged.

## Terminal cycle evidence

The Overwatcher Skill gets one compact example and a negative reminder: `native_active_session_evidence_ref` must be byte-for-byte equal to the existing absolute `path` of one entry in `evidence_refs`, whose lowercase SHA-256 matches the file. A status ID, cycle ID, URI, hash value or prose description is not a reference. Validator behavior remains unchanged.

## Acceptance

- Status-basis same-Session resume closes the reproduced deadlock and can immediately write the next valid cycle.
- Both basis fields or neither field fail closed.
- Non-latest/`IN_PROGRESS`/wrong identity/replaced/stale/non-Supervisor/new-Session cases fail closed.
- The existing cycle-basis route and ordinary cycle `ACTIVE`/`IN_PROGRESS` gates remain unchanged.
- Skill, schema and documentation use the same anomaly-code mapping and terminal evidence structure.
- SLK 4.2.9 passes the complete repository, package and local-install gates without reading or changing R3B or LCaS.
