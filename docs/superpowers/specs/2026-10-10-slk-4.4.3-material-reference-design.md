## 桌面 BI：两层滚动与收起修复

Owner 提供的三张截图显示展开区底部被裁切、收起后窗体留下大块空白并缓慢缩小。本次仅修现有展示和窗口尺寸逻辑，不增加组件服务或修改 SLK 事实数据。

- **外层主列表：** 沿用最多五行 Run 的显示额度，超过额度通过外层纵向滚动条查看。展开内容不扣除这五行额度，而是在原列表高度上增加受限的展开区高度；所有 Run 仍保留，不截断数据。活动与归档内容均应在受限窗口中滚动可达，不能因打开归档再次无限长高。
- **内层展开区：** 角色与 OW 状态保留；CELL 记录最多显示六个单位行，更多 CELL 使用自己的纵向滚动条。六行是上限，不是固定高度：扣除标题栏、Run 主行、角色栏、OW 状态和必要分隔线后，空间不足时减少可见 CELL 行数，不能为凑满六行裁切内容。这里的“六单位行”按六行 CELL 记录计算，不是六个 Run，也不是删除第七行以后的内容。
- **两个层次分开：** 外层滚动 Run，内层滚动当前 Run 的 CELL；溢出时相应滚动条可见并可拖动，键盘可进入两层区域，内层到达边界不继续带动外层。主列表的高度预算不能由内部 CELL 总数决定。
- **唯一展开：** 同一时刻整个桌面 BI（包括已打开的归档区）最多展开一个 Run。展开另一个先收起原来的；再次点击当前 Run 则收起；不影响绿点已读行为。
- **直接缩窗：** 收起后按实际内容高度直接设置窗口尺寸；不增加慢动画、逐像素缩减或轮询补偿。尺寸计算不得依赖自身正在改变的窗口高度；相同目标尺寸不反复设置。窗口保留安全高度上限，屏幕空间不足时优先保证内容通过外层滚动可达，而不是裁切。

检查依据：`RunStrip.tsx` 每行各自持有展开状态，无法互斥；`.cell-list` 无高度上限或 overflow；`.active-run-strips.is-scrollable` 的五行 max-height 包含展开区，且只在超过五个活动 Run 时启用；归档列表没有高度约束。`App.tsx` 从 `.app-shell.scrollHeight` 驱动 ResizeObserver/setSize，但 `.app-shell` 的 `min-height: 100vh` 令测量依赖当前窗口高度，且 scrollHeight 不包括上下边框。前端的最小目标高度 94 与 Tauri `minHeight: 176` 也不一致，需统一必要约束，而不是再加恢复包装器。

### 2026-10-10 深入复测：区分缺陷与设计选择

使用当前未改动的真实 App/RunStrip/CSS 和测试 fixture，在临时目录打包并以独立 headless Edge 执行九组场景；没有接入实际 SQLite、通讯、上传、ntfy 或产品 Run。原生 setSize 被替换为浏览器视口调整并模拟现有 176 最小高度；单独的实验明确标记为 CSS 注入或 94 最小高度对照，不是已实施修复。运行中的 BI 二进制 SHA256 与冻结完整包一致：`c3fc84da4ce8bedcacec870c66c0b377a673ba75936b3b16e3a034f8005b901d`。

准确结论：裁切、尺寸反馈、额度混算、归档无界都已在隔离渲染中复现；“最多六行”和“最多一个展开”是 Owner 选择的改进方式，不是假定旧代码已经承诺的行为。现有测试只检查五/六 Run 时的 CSS 类名，不能证明布局、滚动条或原生 resize 正确。原始复测数据、脚本和截图位于本工作树 `.codex/.tmp/bi-layout-investigation-20261010/`，为临时研究产物，不进入发布包。以上不等同于 Windows WebView2/Tauri 原生实机验收，正式修复后仍需原生验证；没有修改或重启运行中的 BI。

最小实现沿用现有 `App` / `RunStrip` / CSS / 窗口控制：将唯一展开身份上移到 App；主内容共用一个外层滚动区域，活动和归档不再各自无限叠高；分开计算 Run 主行额度与展开区可见高度；限制 CELL 内层滚动并阻止边界串滚；尺寸按实际内容的完整边框盒取整，去除受当前视口反向约束的测量并统一必要最小高度。相较新开弹窗或独立详情面板，该方案保留 Owner 指定的“原位展开，只是变长”。不引入虚拟列表、滚动库或新的后台进程；也不添加第三层滚动、慢动画或定时缩窗补丁。

验收必须覆盖：5/6 个 Run、6/7/16 行 CELL、活动与归档之间切换展开、收起长详情后一次直接缩到内容目标、快速连续切换不会被过期尺寸覆盖、两层实际滚动/滚动条/边界与键盘操作、缩放和有限屏幕高度。DOM 单元测试不能证明实际 CSS 布局或原生窗体效果，另用隔离假数据进行真实布局检查，原生实机未验收时必须明确保留此项，不能冒充已通过。

界面规范使用 `impeccable` 的产品/布局规则，保留既有 LCD 配色、密度与组件；本轮不加 Agent，采用单上下文先人工核对、后机械扫描。扫描当前目标返回零静态布局告警，不代表上述动态布局缺陷不存在；既有装饰和其他未涉及样式不作为本轮重设计对象。

### 多层进度格（Owner 追加）

保留现有比例进度语义，不将进度格误写成 CELL 数量限制；采用自适应层数而不是所有 Run 固定三层：0–8 CELL 为一层八格，9–16 为两层十六格，17 以上为三层二十四格。超过 24 CELL 仍可正常展示，格子按完成比例概览，准确数量继续由旁边 `已完成/总数 CELL` 及无障碍属性提供；提示明确为比例概览，不承诺一格对应某个具体 CELL。没有全部完成时不得因比例取整显示全满；0 CELL 保持空格，不除零。
