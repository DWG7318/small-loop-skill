## 桌面 BI：两层滚动与收起修复

Owner 提供的三张截图显示展开区底部被裁切、收起后窗体留下大块空白并缓慢缩小。本次仅修现有展示和窗口尺寸逻辑，不增加组件服务或修改 SLK 事实数据。

- **外层主列表：** 沿用最多五行 Run 的显示额度，超过额度通过外层纵向滚动条查看。展开内容不扣除这五行额度，而是在原列表高度上增加受限的展开区高度；所有 Run 仍保留，不截断数据。活动与归档内容均应在受限窗口中滚动可达，不能因打开归档再次无限长高。
- **内层展开区：** 角色与 OW 状态保留；CELL 记录按新到旧展示，最新 CELL 在最上方、最老在下方，保留原编号，仅改变展示顺序，不改变计划、执行顺序或验收状态。最多显示六个单位行，更多 CELL 使用自己的纵向滚动条。六行是上限，不是固定高度：扣除标题栏、Run 主行、角色栏、OW 状态和必要分隔线后，空间不足时减少可见 CELL 行数，不能为凑满六行裁切内容。这里的“六单位行”按六行 CELL 记录计算，不是六个 Run，也不是删除第七行以后的内容。
- **两个层次分开：** 外层滚动 Run，内层滚动当前 Run 的 CELL；溢出时相应滚动条可见并可拖动，键盘可进入两层区域，内层到达边界不继续带动外层。主列表的高度预算不能由内部 CELL 总数决定。
- **唯一展开：** 同一时刻整个桌面 BI（包括已打开的归档区）最多展开一个 Run。展开另一个先收起原来的；再次点击当前 Run 则收起；不影响绿点已读行为。
- **直接缩窗：** 收起后按实际内容高度直接设置窗口尺寸；不增加慢动画、逐像素缩减或轮询补偿。尺寸计算不得依赖自身正在改变的窗口高度；相同目标尺寸不反复设置。窗口保留安全高度上限，屏幕空间不足时优先保证内容通过外层滚动可达，而不是裁切。

检查依据：`RunStrip.tsx` 每行各自持有展开状态，无法互斥；`.cell-list` 无高度上限或 overflow；`.active-run-strips.is-scrollable` 的五行 max-height 包含展开区，且只在超过五个活动 Run 时启用；归档列表没有高度约束。`App.tsx` 从 `.app-shell.scrollHeight` 驱动 ResizeObserver/setSize，但 `.app-shell` 的 `min-height: 100vh` 令测量依赖当前窗口高度，且 scrollHeight 不包括上下边框。前端的最小目标高度 94 与 Tauri `minHeight: 176` 也不一致，需统一必要约束，而不是再加恢复包装器。

## Run 暂停、恢复与关闭（Owner 本轮追加）

2026-10-10 Owner 要求本轮同时考虑暂停和关闭 Run 的子 Skill：暂停用于改变参数等，包括更换 SLK 版本；关闭用于 Run 结束后的收尾。两者均是登记 Supervisor 的权利和职责，必须按实际状态完成，不由 Worker、Checker 或 OW 自行决定。此节登记升级范围与拟议最小边界，不表示工具已经实现，也不是当前产品 Run 的暂停、换版或关闭指令。

- **子 Skill 组织：** 拟新增一个 `slk-pause-run` 承载暂停、暂停期间变更与恢复；完善已有 `slk-close-run` 的收尾职责，不新增第二个关闭 Skill。主 Skill 仅增加必要路由，其余说明优先从现有调整、成员与 Temporal 规则移入或引用，不重复堆叠。
- **暂停：** Supervisor 明确指定 Run、原因和计划变更，先阻止本 Run 新派发及自动推进，再组织正在工作的成员到达安全停点、保存结果和交接事实，核实真实停止或安全隔离。未停稳只能记录为暂停处理中，不得宣布已经暂停并同时改动活动调用的参数。保留候选、D0/D1/D2、失败历史、TOKEN、未完成消息与原 operation，不把暂停写成完成或失败，不新建替代 Run。
- **变更与恢复：** Supervisor 在既有 Owner 授权和模型绑定范围内执行参数或 SLK 版本变更，记录变更前后值、影响范围和原登记/合同版本。换版优先复用现有显式合同采用、绑定迁移与预检入口，不只改版本文字或静默覆盖旧记录；尚不支持的变更保持暂停并如实指出限制。恢复前复核受影响的工具、登记和必要正常通讯，确认旧调用不会继续写入、新绑定可用，再由 Supervisor 明确恢复到原未完成节点；不重新施工已验收内容，不重复投递、移动 TOKEN 或抹除历史。
- **共享资源：** Run 暂停不等于 OW Session 退出，也不关闭共享 Temporal 服务。OW 继续如实观察本 Run 的暂停状态及其他绑定 Run；Temporal 保留本 Run 的工作流身份与历史，不能把授权暂停误作故障并自行推进。暂停期间责任计时如何与既有告警协同，须在候选工具设计和验证中明确，不能靠忽略告警冒充已支持暂停。
- **共享 OW 权限边界（Owner 再次强调）：** 本 Run 的 Supervisor 仅能处置本 Run，不能因暂停、换版或关闭本 Run 而暂停、终止或归档共享 OW Session。必须核实 OW 的全部实际绑定；其他 Run 暂停不等于绑定已解除。仍有任何其他绑定 Run 时，OW 持续服务，不受当前 Run 的收尾影响。只有全部绑定已解除，并完成既有 Supervisor 停止确认及退出 Hook 二次确认后，才可停止或归档 OW Session；未证明时保持，不凭本 Run 的状态推断整个 OW 已可关闭。
- **关闭：** 正常完工仍沿现有 `D2_PASSED → terminal snapshot → OW final cycle → close-overwatcher → RUN_CLOSED → close-role` 顺序，由 Supervisor 负责逐项执行并核对收据与真实状态；D2 PASS 不等于收尾完成。随后核实 Worker/Checker 本轮调用结束、角色/端点按准确身份归档，关闭本 Run 的 Temporal 工作流对和待处理计时/操作，再在无相关活动进程时清理本 Run 专属可重建缓存及确认过期的资源占用。成果、原件、失败历史和在线存档保留，仅归档，不删除；共享 OW 只解除该 Run 绑定，仍有其他 Run 时不能停 Session 或共享服务。
- **最终确认：** Supervisor 汇总实际完成项、遗留项、验收限制与证据位置后再向 Owner 报告。关闭部分失败必须保留已完成步骤和下一动作，原请求可安全续做；不得用已发命令、投影归档或单条成功回执代替全部后台已停止。Worker/Checker/OW 只能请求、执行分配的停止动作或报告事实，不能自行恢复、换版或宣布 Run 已关闭；Owner 的明确叫停要求始终优先。

拟验收场景：施工中暂停并停稳；暂停期间不派发且不触发工程重复执行；改参数/版本后原地续接与历史可追溯；未停稳或变更预检失败时不能恢复；未经 Supervisor 决定不能自行暂停/恢复/关闭；部分收尾失败后同请求续做不产生重复副作用；共享 OW/Temporal 不影响其他 Run；无须删除成果即可完成归档。负面提示优先替换现有冲突或含糊描述，不额外引入审批层、定时任务、常驻组件或第二套状态系统。

## 第七项：整体逻辑梳理、调试与瘦身（最后执行）

Owner 明确第七项必须在前六项施工及阶段验证完成后执行，不能提前或混入前六项边修边重构；前六项自身必要的诊断、修复和测试照常进行。本项不只是减少代码，还要梳理并调试整个 SLK：用现有外部检查工具配合 LLM 核对板块之间的调用、数据流、状态与权限关系，先查清并修复问题，再精简。代码和 Skill 文案分开评估，不把少行数直接等同于更健康或更省 Token。

1. **划清板块与逻辑关系：** 按现有材料/通讯、OCRV/DSH 适配、OW、Temporal、中央状态/TOKEN、BI/WebBI/ntfy、Skill/安装验证列出责任、入口、文件和依赖，标清谁调用谁、谁产生/读取/写入哪些事实、谁决定下一动作。先做文件与责任映射，不为凑模块数量搬目录或造抽象层。
2. **整体调试与健康检查：** 复用现有测试、类型/静态检查、编译和仓库验证，由 LLM 逐板块及跨板块核对实际调用、权限、状态转换、正常路径、异常恢复、历史兼容与重复约束；串联准备、正常通讯/接管、TOKEN 交接、D0/D1/返工、D2、OW/Temporal 保障、暂停换版恢复和最终关单，排查断链、重复执行、循环依赖和记录/事实矛盾。静态扫描/搜索结果不单独证明代码无用；发现可靠性问题先复现、归因和修复，建立带明确限制的可复测基线，不跳过失败用例来制造通过，也不以逐块单测通过代替整链调试。
3. **再做小步瘦身：** 优先删除已证实无调用且无兼容责任的旧代码，合并确实同语义的重复实现，移除已确认无必要的等待、包装和检查；不因看起来相似就合并不同角色或 Run 的权限路径。每个删改点保留依据并独立复测，跨板块大改先列出建议，不混入这一轮小修。
4. **Skill 瘦身：** 以替换/归并重复说明为主，条件性细节放在已有按需参考中；保留角色权限、正常通讯、D0/D1/D2、失败处理和必要负面提示。不能靠把全部正文挪到每次仍须读取的文件、删验收条款或加硬字符上限冒充省 Token，也不新建成套重复规则。
5. **同候选验收与报告：** 对最终候选运行相应板块和全仓回归，比较删改前后行为，覆盖错误消息/重复投递/多 Run 隔离/真实收尾等必要负例。分别报告实际删改点、文件/行数变化、消除的重复路径、验证证据和未验证风险；不设减行目标，不把代码减少推算成未经测量的 Token 节省。源码、成果与历史证据不作为“瘦身垃圾”清理。
