# SLK 4.2.11 Engineering Role Close Design

## Scope

SLK 4.2.10 can close a Run and its optional Overwatcher, but has no supported terminal action for the Run's exact Checker or Worker. The resulting central facts remain `lifecycle=active`, `display_state=ready`, and endpoint `active` after `RUN_CLOSED`. This patch adds only that missing post-close action. It does not change CELL, D0, D1, D2, TOKEN movement, role topology, communication routes, or product repositories.

## Considered approaches

1. **Chosen: an explicit `slk-state close-role` transaction.** Reuse the existing role, endpoint, credential, work-event, runtime-snapshot, query, and export structures. This preserves an auditable action and exposes omissions instead of silently hiding them.
2. Auto-close Checker and Worker inside `RUN_CLOSED`. Rejected because it would conflate engineering closure with member retirement and make a missed close impossible to observe or repair independently.
3. Reuse `replace-role` or add a lifecycle service. Rejected because replacement invents a successor and a service/daemon would be disproportionate.

## Contract

- The current Supervisor authenticates the request and names the exact current role instance. The target must be `checker` or `worker`; Supervisor and Overwatcher are rejected.
- The Run must already have a matching terminal event and terminal projection. The target must still be active, must belong to that exact Run and role, and must not hold the current SLK TOKEN.
- One immediate transaction appends `ROLE_CLOSED`, sets the target lifecycle to `exited`, retires its active endpoint, revokes its active credential, and advances the existing runtime snapshot without changing TOKEN or terminal verdicts. No successor is created.
- The exact same request ID and content is idempotent. Reuse with different content is a conflict. Wrong Run, role, instance, credential, open/nonterminal Run, missing final event, or TOKEN ownership fails closed.
- `slk-bi-query` derives `display_state=archived` from the terminal role event/lifecycle while preserving the historical role, endpoints, and audit event.
- Existing closed Runs may use the same command after adopting 4.2.11 tooling. This is a post-close administrative reconciliation; it does not reopen or reinterpret the Run.

## Skill correction

`slk-close-run` and `slk-manage-team` will name the exact command and verification facts. They must not call a planned Session archive complete until central lifecycle is `exited`, display state is `archived`, and no active endpoint remains. Overwatcher keeps its separate existing close path; Supervisor remains active.

## Acceptance

- A closed Run can close its exact Checker and Worker once and replay the same requests safely.
- Open/nonterminal Run, wrong target role or identity, wrong credential, TOKEN holder, mismatched replay, and attempts to close Supervisor or Overwatcher are rejected.
- The transaction preserves Run closure, D1/D2 events, TOKEN history and owner, and creates no successor.
- Query/BI immediately reports archived roles and retired endpoints while retaining history.
- A stress scenario rejects the claim that active/ready means archived when the close entry is absent.
- The real Run `SLK-RUN-LCAS-RC08-JSONL-COMMIT-AWARE-ACK` is reconciled through `slk-state`, not direct SQLite edits.

## Compatibility and non-goals

SLK 4.2.11 remains schema-v8 compatible and uses no new table. It does not close Supervisor, replace Overwatcher closure, archive native Agent Sessions by itself, create a daemon, schedule work, or modify LCaS product files.
