# SLK 2.6.0 Controllable Model Policy Design

Date: 2026-08-06
Status: Owner-approved candidate design
Scope: Small Loop Skill only

## Objective

Replace SLK 2.5.0's fixed Patrol model with a versioned, auditable model-selection
policy for the existing Control responsibilities, Worker, and non-authoritative Run
Patrol. The change records capability equivalence, actual model, reasoning effort,
selection level/reason, and revalidation evidence without adding a role,
conversation, GO state, verification layer, or runtime scheduler.

Target version is `2.6.0` because this changes normative role readiness and runtime
evidence while preserving the 2.x topology and D0-D3 contract.

## Considered approaches

1. **Replace the fixed Patrol string only.** Smallest diff, but it cannot govern
   Worker Luna exceptions, Sol escalation, equivalent substitutes, or silent model
   switches. Rejected as incomplete.
2. **Scatter model fields through every existing receipt.** This gives local
   visibility but duplicates policy and makes cross-role switch history difficult
   to validate. Rejected because it increases drift and cognitive load.
3. **Add one versioned `MODEL_BINDING_TRACE` and reference it from existing runtime
   records.** Selected. It centralizes policy evidence, keeps receipts lightweight,
   and lets the existing readiness/index validators fail closed without changing
   execution topology.

## Binding policy

The GPT reference matrix is:

| Selection level | Eligible role/scope | Required work class | Reference model |
| --- | --- | --- | --- |
| `DEFAULT` | every technical role and Run Patrol | ordinary technical work or non-technical Patrol | `gpt-5.6-terra` |
| `CELL_LOW_RISK_EXCEPTION` | Worker, exact CELL/Round only | contract-marked fine-grained and low-risk CELL | `gpt-5.6-luna` |
| `HIGH_DIFFICULTY_ESCALATION` | technical role, bounded GO/CELL/Round | high-difficulty correction, root-cause diagnosis, or complex rework | `gpt-5.6-sol` |

All three reference bindings use `xhigh`. `ultra` is valid only with an explicit,
item-specific Owner authorization reference. `gpt-5.5` and every older/lower GPT
model are always forbidden, including under Owner authorization. Cost or
convenience is never a selection reason.

Run Patrol follows the `DEFAULT` Terra class. It has no implicit Luna exception.
Owner may explicitly select a proven capability-equivalent Terra-class substitute,
but Patrol remains non-technical and receives no D0-D3 or progress authority.

An actual non-reference model is allowed only when its binding names the applicable
GPT reference model, matching capability class, `PROVEN_EQUIVALENT` status, and
immutable equivalence evidence. Exact GPT reference bindings use
`EXACT_REFERENCE`. The validator does not infer equivalence from branding or free
text.

## Machine-readable record

`MODEL_BINDING_TRACE` is the thirteenth runtime record type. It is versioned,
history-immutable, and contains ordered binding entries. Every entry records:

- binding ID/version/status and immutable scope;
- one scalar role and role-instance ID;
- RUN/GO/CELL/ROUND scope identifiers;
- selection level, work class, selection reason, and reason evidence;
- reference model, actual model, capability class, equivalence status/evidence;
- reasoning effort and optional exact Owner ultra authorization;
- CELL granularity/risk/contract authorization facts where applicable;
- readiness, role-isolation, and verification gates;
- predecessor/switch identity and switch evidence;
- immutable evidence references.

The trace requires separate current bindings for Supervisor, Checker, Verifier,
Worker, and Patrol. Multiple roles may use the same actual Terra model, but never
share a binding ID or authority. Model sameness does not collapse role,
conversation, candidate, environment, or receipt isolation.

For one role and one exact scope, binding versions are contiguous. Version one has
no predecessor. A changed actual model or reasoning effort requires a new binding
that immediately supersedes the prior binding, records a switch reason/evidence,
and reruns readiness, isolation, and verification gates. Omitting this history is
`SILENT_MODEL_SWITCH` and fails closed.

## Existing-record integration

- `RUN_RUNTIME_CONTRACT` freezes a versioned/hash-bound model-trace reference and
  binds Patrol to a current Patrol binding instead of a fixed Luna constant.
- Each formal runtime-index dispatch names the Worker binding used for that exact
  dispatch. The index validates role and scope coverage against the embedded model
  trace.
- `RUN_PATROL_RECEIPT` names its binding and must match the trace's actual model and
  effort.
- D0, D1, D2, D3, Supervisor Run receipt, and versioned amendment templates gain a
  `model_binding_ref`; this is evidence binding, not a new verification layer.
- CELL Contract gains explicit granularity/risk/model-selection facts. Only these
  frozen facts can authorize the Worker Luna exception.
- `RUNTIME_SIMULATION` adds exact positive and fail-closed scenarios for the new
  policy.

## Validator invariants

The validator accepts Terra default, the strictly qualified Worker Luna exception,
Sol only for the three approved high-difficulty work classes, and proven equivalent
substitutes. It rejects:

- GPT 5.5 or lower and unparseable GPT claims;
- `ultra` without exact Owner authorization;
- Luna outside Worker, without exact CELL/Round scope, without fine-grained/LOW
  contract facts, or with cost/convenience as reason;
- Sol for ordinary implementation, ordinary inspection, or Patrol;
- capability-class/reference mismatch or unevidenced equivalence;
- missing readiness/isolation/verification PASS;
- duplicate binding IDs, role/scope ambiguity, non-contiguous revisions, or silent
  switches;
- an index dispatch or Patrol receipt bound to the wrong role, scope, model, effort,
  trace version, or superseded binding.

All checks use explicit exceptions rather than Python `assert`, so critical
negative paths remain active under `python -O`.

## Testing and acceptance

TDD adds RED cases before validator changes. Required acceptance includes:

- Terra default passes for all separately bound roles;
- fine-grained/low-risk Worker CELL to Luna passes;
- high-difficulty correction/root-cause/complex rework to Sol passes;
- a proven equivalent non-GPT substitute passes;
- GPT 5.5/lower, unauthorized ultra, unjustified Luna, ordinary-work Sol,
  non-equivalent substitution, and silent switch fail closed;
- same actual model across roles preserves distinct role bindings;
- Patrol uses Terra by default and cannot claim technical exceptions;
- runtime contract/index/Patrol references bind the current trace;
- root/install mirrors, schema, simulation set, Manifest, version, and report remain
  consistent.

## Explicit non-goals

This version adds no new visible conversation, role, D4, GO state, message bus,
model router, cost optimizer, provider benchmark system, automatic model switch,
new Worker, parallelism, CLK/GLK behavior, or LCCoding product-definition logic.
It does not change wake, Patrol interval/checklist, progress, capacity, Pin,
candidate, or D0-D3 decision semantics.
