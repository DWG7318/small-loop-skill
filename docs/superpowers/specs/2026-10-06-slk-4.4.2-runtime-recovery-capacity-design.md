# SLK 4.4.2 Runtime Recovery and Capacity Design

- Date: 2026-10-06 (Asia/Shanghai)
- Status: approved local implementation contract
- Baseline: SLK 4.4.1 at `6c12be8bb1f56793e9134a2a05ffa8f79ad006b2`
- Target: SLK 4.4.2; BI/WebBI remain 1.1.0
- Rollout: source candidate only; no install, merge, push, tag, Release, or product-Run adoption in this phase

## Decision

4.4.2 closes observed gaps in the existing RoleHost, Temporal, OCRV and OW paths. It adds no role, scheduler, daemon, message bus, state machine or wmux dependency. Supervisor, Checker, Worker, OW, TOKEN and D0/D1/D2 authority remain unchanged.

The release follows one rule: preserve immutable engineering evidence, then make the already-owned remaining suffix consumable by the exact registered host. A transport timeout, output-size estimate or wrapper result never becomes an engineering verdict.

## 1. Active Supervisor decision submission

A Supervisor decision must not depend on the delivery parent waiting until the whole Codex turn exits.

- The prepared prompt identifies one deterministic `supervisor-result.json` and one public `submit-supervisor-decision` entry.
- The entry is callable only inside the exact registered Supervisor Session with the hash-bound RoleHost environment.
- It validates the frozen endpoint, incoming envelope, native start, result schema, source message, scope, plan/runtime boundary and sealed Supervisor authority before recording or handing off.
- It reuses the existing `_supervisor_result` path. It does not reinterpret D1, create a second decision contract or expose credentials.
- Exact replay returns the first receipt. Drift, wrong Session, wrong role, wrong message or changed result fails before state write or downstream delivery.
- Parent `CODEX_TURN_TIMEOUT` may remain as immutable transport evidence; a valid submitted decision is not erased or replayed because the turn later ends.

## 2. Late Desktop readback

When a Desktop send was accepted but the first bounded read did not yet prove its native item, recovery reads the original attempt without sending again.

- `consume-desktop-readback` requires the frozen endpoint/envelope, `desktop-send.json`, original prompt hash and exact target/caller/host/workspace.
- It accepts exactly one later platform item containing the original delivery bytes and one matching target turn.
- It writes only the missing readback/start/completion evidence. Existing bytes are immutable and replay is idempotent.
- Missing proof remains `CODEX_DESKTOP_READBACK_UNPROVED`; multiple matches, changed identity, wrong scope or wrong round fail closed.

## 3. Canonical Checker attempt root and explicit suffix failure

Every Worker-owned Checker start in a Temporal Run uses `temporal.attempt_root`. The Worker continuation may stage endpoint/envelope files locally, but it cannot invent `worker-continuation/checker-attempts` as a second physical history.

Legacy 4.4.0/4.4.1 continuation records remain readable. New 4.4.2 records bind the canonical root and reject drift. An existing exact Checker attempt is reused; no duplicate OCRV start is permitted.

If the transport job recorded an explicit `HOST_HANDOFF_FAILED`, OW inspection reports the concrete handoff failure immediately. `COMPLETION_GRACE` applies only when no explicit suffix failure exists.

## 4. OCRV advisory sizing

OCRV capacity protects model/time cost, not source line count or file count.

- `max_tokens`, `max_tokens_budget` and `timeout_minutes` remain positive, preparation-frozen execution limits.
- Historical seven-field 4.4.0/4.4.1 requests remain hash-stable and readable, but `max_background_characters`, `max_background_bytes`, `max_changed_lines` and `max_segment_paths` are advisory observations only.
- New 4.4.2 requests record the three executing limits plus observed background/path/line metrics. No fixed `800` line, `2` file, `8000` character or `12000` byte gate blocks review.
- Segmentation is allowed only for real OCRV coverage/continuation semantics, not because a numeric line/file threshold was crossed.
- A 1077-line one-file candidate and a three-file candidate reach real preflight/review. Tool inability remains `INCOMPLETE`, never D1 `FAIL` or product rework.

Prepared limits are frozen by readiness/team preparation and copied exactly into every request. Agents may not silently change them during a CELL.

## 5. Bounded evidence and finding payloads

Compact evidence never silently truncates identity-bearing lists. A changed-path summary contains `total`, `shown`, `omitted` and the absolute source evidence path; the full list stays in the referenced local evidence.

OCRV findings retain severity, message, location, criterion and evidence. Provider reasoning/thinking is excluded from transport findings and D1 escalation payloads because it is neither required evidence nor a second verdict. Exact native output remains locally traceable.

## 6. OW Worker-boundary inspection

When the authoritative TOKEN holder is Worker, every OW cycle performs exactly one credentialless, read-only `inspect-worker-completion` for the current Run/CELL/attempt/message before classifying the cycle.

- The current responsibility and next expected transition are derived from one authoritative runtime revision before choosing artifacts.
- Missing `WORK_STARTED` is not proof that Worker never took over.
- The inspection receipt is hash-referenced by the cycle; missing, duplicate, stale or wrong-scope inspection fails closed.
- Old OCRV attempts, old CELL D1 or unrelated Run data cannot prove the current handoff.

OW still only observes and reports. It does not retry, route, write BI/TOKEN or decide D1/D2.

Concrete non-secret state-core rejection details pass through `overwatcher-admin` as bounded error code/message evidence. Secrets, commands, credentials and arbitrary stdout remain suppressed; the generic closed-result error is only the fallback when no safe structured rejection exists.

## 7. Temporal reload race and build isolation

`reload-temporal-worker` treats an already-exited old parent as an idempotent stop result only after verifying the same Start/Run workflow IDs, native Run ID, task queue and startup fingerprint. A live wrong process, identity drift or unverifiable exit still fails.

Cargo work uses a Run-owned writable target/cache path. Another project or Run cache is never borrowed as a workaround.

## 8. Supervisor plans for the actual DSH Worker

After the engineering solution and acceptance outcome are fixed, Supervisor must still size the serial plan for the registered DSH Worker rather than for Supervisor's own stronger reasoning capacity. A large CELL that combines too much implementation, context recovery, testing and evidence is split before dispatch into dependency-ordered small or medium CELLs that can each be implemented, D0-checked and independently D1-checked.

The split preserves the original Run outcome, acceptance strength and serial topology. It is not a way to add scope, turn commands into micro-CELLs, move design work to Worker, or let Worker split its own assigned CELL. Supervisor records the capability/cumulative-load basis and Checker still performs the ordinary pre-dispatch capacity check. Repeated rework or `CELL_SCOPE_EXCEEDED` forces Supervisor to reconsider the remaining undispatched CELL sizes.

The operating target is that most CELLs pass D1 on the first attempt and one CELL has at most one ordinary formal D1 failure. A second consecutive formal D1 failure for the same CELL stops ordinary rework: Supervisor compares both failure rounds, version-replans the unaccepted remainder into dependency-ordered small or medium successor CELLs with independent D0/D1, and returns the revised plan to Checker for dispatch. The two failures remain visible and the original goal and acceptance strength do not change. `INCOMPLETE`, tool/transport failure and duplicate receipts do not increment this count. If no honest split remains, Supervisor keeps the work blocked and chooses another explicit route instead of starting a third ordinary rework.

## Compatibility and non-goals

- 4.4.0/4.4.1 immutable requests, receipts and histories are not rewritten.
- DSH/OCRV truncated display output must lead to the referenced original file; a summary is never complete evidence.
- wmux remains a recorded future device substrate and is explicitly outside 4.4.2.
- BI/WebBI stay at 1.1.0 and receive no new engineering fields or authority.
- The active product Supervisor and Run remain on their current installed version until the Owner separately requests deployment.

## Acceptance

At minimum, normal and optimized-mode tests prove: active submission survives parent timeout; wrong Session/result/scope rejects; late Desktop proof consumes without resend and rejects ambiguity; Temporal Worker continuation uses one canonical attempt root; explicit handoff failure bypasses grace; 1077-line/three-file candidates reach OCRV; old capacity records remain readable but non-executing; configurable token/time limits remain exact; compact paths disclose omission; thinking is absent from escalation; Worker-held TOKEN cycles require one current inspection; safe OW rejection details survive; reload exit race is idempotent only for the same identity; Supervisor pre-splits a large frozen solution for DSH without changing acceptance; a second consecutive formal D1 failure forces versioned split/replan rather than a third ordinary rework; Worker self-split and command-sized micro-CELLs reject.
