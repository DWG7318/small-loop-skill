# SLK 4.3.6 Checker Post-D1 Suffix Design

Date: 2026-10-01

Status: Owner-approved local correction

## Problem and boundary

An authenticated OCRV recovery can record the original `D1_FAILED`, but the one-shot Checker harness then exits. No deployed native entry can form the existing `D1_FAILURE_ESCALATION`, prove that the exact Supervisor started, and atomically move TOKEN with the sealed Checker credential.

This correction adds one FAIL-only suffix. It does not rerun review, decide D1, create a role, dispatch Worker, produce a rework directive, change the state model, or introduce a daemon. PASS and INCOMPLETE cannot enter it.

## Closed request and identity

`slk.checker-post-d1-request/v1` binds method version, invocation, Run/GO/CELL/attempt, plan/runtime/TOKEN revisions, Checker identity, original D1 failure event, current runtime projection, original OCRV native attempt, Supervisor endpoint, sealed Checker credential path, standard state/transport commands, escalation evidence root, round, CELL goal, criteria, findings, reproduction, expected result, evidence references, and timestamp.

The Tool requires the current projection to end at the exact Checker-authored `D1_FAILED`, with TOKEN still at that Checker. It binds the event's `candidate_message_id` and recorded native hashes to the immutable OCRV attempt, obtains the candidate from that attempt's closed `CANDIDATE_READY` envelope, and derives `failed_candidate_sha256` from the canonical candidate object. The sealed credential is unprotected only inside the Tool, used for `authenticate-role` and the final atomic commit, never printed or passed to transport.

## Two-phase flow

1. `D:\OCRV\slk-checker.cmd --slk-post-d1 --request REQUEST --output PREPARED` invokes the managed `checker-escalate-d1` command.
2. The Tool writes one deterministic Checker→Supervisor `D1_FAILURE_ESCALATION`, calls existing `send`, then the single exact retry. For the current active Desktop writer it calls existing `prepare-desktop-current-turn` and returns `DESKTOP_BRIDGE_REQUIRED` with the immutable bridge request.
3. The Codex Desktop host sends that exact prompt and records the existing closed host receipt after platform readback.
4. The same native command is invoked with `--host-receipt RECEIPT --output COMMITTED`. It re-authenticates the same Checker and revalidates unchanged runtime/D1 evidence, calls existing `complete-desktop-current-turn`, validates the resulting native-start receipt, and calls existing `slk-state commit-delivery-start` with TOKEN sequence `current+1`.
5. Only a committed result naming the registered Supervisor is success. Any changed identity, PASS/INCOMPLETE, missing evidence, unproved Desktop start, stale runtime, wrong TOKEN owner, or commit mismatch fails closed.

## Files and acceptance

Implementation is isolated in one transport module, one OCRV native wrapper, one closed schema, the existing CLI and integration installer, focused tests, and short transport documentation. Acceptance requires RED/GREEN coverage for prepare, complete, identity drift, non-FAIL, missing start, wrong commit result, CLI exposure, installer rollback, ordinary/optimized full suites, repository/package verification, and byte-verified deployment of only the changed managed transport and OCRV integration surface.
