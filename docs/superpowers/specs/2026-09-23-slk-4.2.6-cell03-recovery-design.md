# SLK 4.2.6 CELL03 Recovery Design

**Input:** immutable LCaS CELL03 postmortem for `SLK-RUN-LCAS-RC08-GUI-WINDOWS-STABILITY-R3B`.

**Boundary:** correct only identity, communication and role-guidance gaps exposed by the accepted second D1 attempt. Do not change the product candidate, advance CELL04/D2, add an orchestrator, introduce Temporal, alter BI authority, or change model policy.

## Design

1. Add one Supervisor-only `resume-overwatcher-turn` mutation. It preserves role, Session, binding and old cycles; it accepts only a new turn following the exact latest anomalous cycle.
2. Make Worker completion evidence exact to run, CELL, attempt, candidate, source message and deterministic handoff message. Other-attempt or other-candidate D1 evidence cannot prove handoff.
3. Normalize initial `d1_criteria` and rework `acceptance_criteria` into the same Checker payload, rejecting conflicting dual definitions.
4. In active-writer recovery, inspect the existing active task/turn and steer it directly. Commit TOKEN only after matching start evidence.
5. Run detached Windows transport headlessly with job breakaway so a one-shot DSH exit does not own the long OCRV process lifetime. Treat transport/tool failure as INCOMPLETE or `TRANSPORT_FAILED` in the same D1 attempt.
6. Replace ambiguous Skill wording: Worker role completion includes D0, candidate record and one handoff; Overwatcher reports then pauses and never implements or judges D1.

The state core remains an identity/evidence authority, not a scheduler. No new background service, heartbeat, timer, role or BI writer is introduced.
