Closed Worker outcomes are `completed`, `incomplete`, `blocked`, `execution_failure` and `timed_out`. Missing/extra fields, mismatched attempt identity, a candidate on a non-completed outcome, or a result inferred from process exit fail closed. The inspector maps these to one immutable attempt-bound observation without rewriting engineering facts.

## Writes, capacity and continuity

| Surface | Pre-start or continuation gate | Durable fact on failure | Result |
|---|---|---|---|
| DSH repository | worktree root, Git common dir, `objects`, `refs` and index location writable; common dir must remain inside supported Worker root | closed Worker blocker with phase/cause/evidence | PASS |
| SLK state/evidence/transport roots | configured roots exist and exact role credential/scope validates | transport/process result and immutable evidence path/hash | PASS |
| OCRV review | changed paths and criteria become ordered capacity-sized segments | completed segment request/result/native logs plus root incomplete progress | PASS |
| Codex active writer | at most 100 cursor pages, no cursor loop, exactly one current active turn | original failed delivery and `CODEX_ACTIVE_WRITER_UNRESOLVED` | PASS |
| Overwatcher | one binding, distinct status/incident ID per occurrence, bounded same-process wait | OPEN/ACK/RESOLVED incident chain | PASS |

Active-writer table tests cover embedded, omitted and empty turn lists; page-two current turn; `inProgress`, `interrupted`, `notLoaded`, stale, missing, duplicate, cursor-loop and page-limit evidence. Recovery is one new message bound to original message ID, payload hash, exact thread and proven current turn; no delayed replay or blind resume is allowed.

Two or more Overwatcher pause/resume cycles on one binding use distinct incident IDs and resolve only the exact latest occurrence. A normal cycle does not end the foreground turn: it immediately performs another bounded `wait-for-change`. A real anomaly, terminal closure or truthful bounded blocker is an exit; heartbeat/timer automation is not introduced.

## Migration, package, BI and Temporal-off

- Schema remains v8; migrations remain contiguous `0001.sql` through `0008.sql`.
- Explicit `4.3.0 -> 4.3.1` adoption preserves Run ID, plan revision, TOKEN holder/sequence, role/session endpoints, D0/D1/D2 facts, candidates, attempt directories, Overwatcher binding/history and uncommitted product changes. Install alone neither adopts nor resumes a Run.
- The local package contains all 15 Skills, contracts, state/transport/runtime/maintenance documents, OCRV and optional Temporal integrations, schema migrations and exactly five managed binaries. Repository, package and installed manifests bind every byte.
- BI continues to label the Run's frozen effective SLK version separately from the installed current tool version; it remains read-only.
- Temporal imports and service availability are optional. Direct-mode tests execute without the Temporal SDK/service, and no workflow owns D0/D1/D2, TOKEN, role or BI authority.

## Same-class findings and corrections

| Finding | Shared root cause | Correction | Regression evidence |
|---|---|---|---|
| linked DSH worktree could start although Git common store was unwritable | readiness checked only visible worktree | resolve/probe actual common store and reject unsupported outside-root layouts | `test_workspace.py`, `test_dsh_adapter.py` |
| real Worker failure collapsed to missing result | result contract represented success only | closed truthful non-completed outcomes and immutable inspector | `test_worker_completion.py`, `test_cli.py` |
| rework authority did not match live communication | event owner/predecessor were under-specified | Checker writes failure; Supervisor writes exact successor request | Rust `write_flow.rs` |
| Codex active writer could not be proven from first page | read path treated partial embedded state as complete | bounded cursor traversal and exactly-one-current-turn proof | `test_active_writer.py` |
| repeated Overwatcher recovery collided or ended after one cycle | incident identity reused binding and prompt ended turn | occurrence-bound IDs and same-turn bounded wait | Rust `overwatcher.rs`, Skill tests |
| OCRV host cliff discarded long-review progress | monolithic review/timeout had no durable sub-results | ordered durable segments and aggregate-only D1 | `test_ocrv_adapter.py` |
| context compaction mixed an old WMUX topic into the active SLK maintenance turn | conversation summary was treated as authority | re-read central state/current Run/plan/TOKEN after restoration; reject conflicts | `test_skill_collection_300.py` |

No additional Scheduler, Runtime, role, heartbeat, daemon, BoM path or product mutation was introduced. External provider uptime and platform context-window limits remain outside SLK; their observed failures must still produce durable incomplete/blocker evidence rather than inferred completion.
