# SLK 4.4.2 local compatibility and adoption

4.4.2 is an adjacent, explicit method adoption from 4.4.1. Installing the package does not resume a Run, dispatch a CELL, start or reload Temporal, replace a role, modify BI/WebBI, or change product files.

At an Owner-selected stable Supervisor boundary, preserve the exact Run identity, four role bindings and Sessions, plan/CELL history, TOKEN, candidates, D0/D1/D2, OW cycles, transport attempts and Temporal workflow histories. Submit one hash-bound `4.4.1 → 4.4.2` adoption through the existing Supervisor administration path. Old 4.4.0/4.4.1 requests stay immutable and are consumed only through their existing compatibility paths; they are never relabelled.

Before the next dispatch, produce fresh 4.4.2 readiness and Role Eval evidence. If no source exists, create exactly one disposable single-CELL Run: place runtime evidence under `slk-conformance/<SLK-CONFORMANCE-…>`, bind Worker to one separate clean, fixed-HEAD, no-remote sample Git while every other role retains its true native workspace/cwd, bootstrap its unique Temporal pair, then explicitly admit it through `ISOLATED_CONFORMANCE_SAMPLE`/`preflight-conformance-sample`; it cannot carry product work. After its real seven legs, seal the source. Product startup uses its own minimal bootstrap, captures native identity, freezes identity-aware RoleHost/OW evidence and a `PRODUCT` config, then runs `preflight-new-run` and `slk-temporal-admit`. An already-running Codex Desktop Overwatcher is preserved in place: the Supervisor records one hash-bound read-only attestation of its exact Run/role/endpoint/thread/turn/platform-input identity, selects standard-adapter v2, and every audit re-reads only the last turn's compact control receipt. This neither replaces the OW nor rewrites prior history. `PAIR_CREATED`, `AWAITING_ADMISSION`, guessed IDs, a custom echo adapter, sample-mode product dispatch or product replay cannot qualify. New OCRV work freezes `max_tokens_budget=0`, `timeout_minutes=0` and explicit template-default `max-tools=0`; context/size estimates are advisory, long evidence uses path/hash, and verified native work is not killed by endpoint timeouts. Confirm the canonical Checker attempt root and current role endpoints/credential consumers. Supervisor reviews remaining undispatched CELL sizes against actual DSH capability and cumulative load.

An in-flight 4.4.2 Worker stopped only by the Windows verbatim `slk-cargo` target/MSVC C1083 incident may use the closed `prepare-pre-d0-blocked-recovery` path. The Supervisor must capture a fresh runtime projection and bind the exact corrected Tool, state config, Run project/data-root spelling, existing `PROTOC` executable, clean existing candidate and D0 command. Preparation is read-only. The Tool keeps the configured data-root identity unchanged and normalizes only the child Cargo target spelling. After ordinary delivery, only the original authenticated Checker resumes the same Worker Session once; successful D0 continues through the ordinary Worker candidate suffix and real OCRV D1. A different blocker, pre-existing D0/candidate event, changed Session/commit/path/hash/environment, previous recovery evidence or stale runtime revision remains blocked. Never overwrite or relabel the original blocked result.

The ordinary loop still belongs to Checker and Worker. D1 INCOMPLETE records the exact native reason and uses `checker-manage-incomplete` to send one closed `D1_INCOMPLETE_ESCALATION` plus TOKEN to Supervisor. Supervisor records one bounded action (`WAIT_FOR_NATIVE_WORK`, `ADJUST_CAPACITY`, `ADJUST_ENVIRONMENT` or `MECHANICAL_RECOVERY`) without inventing FAIL/rework/D1. WAIT stays at Supervisor; every other action returns the unchanged candidate to the original Checker as `D1_MANAGEMENT_RETURN`. That review uses the normal unlimited aggregate budget/timeout and template-default tool rounds, corrects the same D1, and continues through the ordinary suffix; it neither deletes a consumed finite-budget marker nor starts another finite continuation. The first formal product D1 failure may use the bounded same-CELL rework path. A second-or-later formal D1 failure makes the old RoleHost return `ROLE_HOST_CELL_SPLIT_REQUIRED`: Supervisor compares both rounds, consumes sealed `supervisor-admin revise-plan`, freezes a new revision Host, updates the standard Temporal Run config, and returns the first successor through normal `Supervisor → Checker CELL_DISPATCH`. INCOMPLETE, tool/transport failure and duplicate receipts do not count. If no honest split remains, keep the Run blocked rather than dispatching Worker directly or issuing another ordinary retry.

Historical OCRV attempts with a positive, explicitly frozen aggregate budget keep their existing exact recovery contracts; an ordinary terminal that is INCOMPLETE only because every selected item stopped on that budget may use `resume-terminal-budget-checker` after Owner authorization. Preserve candidate/attempt/evidence; hash-bind a finite limit above old and observed use plus exact version/rule/runtime/RoleHost identities, and use the read-only preparer rather than hand-authoring. Native resume must create a separately recorded child Session with exact parent lineage. Its narrow rule-identity compatibility and partial-continuation routes remain immutable, but their one-shot markers prevent duplicate side effects rather than imposing a permanent engineering-attempt quota. Any resulting INCOMPLETE takes the new management exit; corrected PASS/FAIL uses the existing sealed suffix. Normal new work does not inherit those legacy finite budgets. A saved exact Desktop readback is consumed without resend; stale identity, changed candidate/Host, forged lineage or product FAIL reinterpretation remains blocked.

Terminal migration keeps credentials sealed: use `supervisor-admin close-overwatcher` with the exact saved OW credential and final cycle, then `supervisor-admin close-run` for the sole `RUN_CLOSED` event, then `supervisor-admin close-role` for Worker and Checker. Do not decrypt a role credential or substitute an ordinary shell command.

BI/WebBI remain 1.1.0. No Docker installation, extra role, scheduler, daemon, wmux substrate, push, tag or Release is part of this migration.
