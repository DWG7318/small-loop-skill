# SLK 4.4.2 local compatibility and adoption

4.4.2 is an adjacent, explicit method adoption from 4.4.1. Installing the package does not resume a Run, dispatch a CELL, start or reload Temporal, replace a role, modify BI/WebBI, or change product files.

At an Owner-selected stable Supervisor boundary, preserve the exact Run identity, four role bindings and Sessions, plan/CELL history, TOKEN, candidates, D0/D1/D2, OW cycles, transport attempts and Temporal workflow histories. Submit one hash-bound `4.4.1 → 4.4.2` adoption through the existing Supervisor administration path. Old 4.4.0/4.4.1 requests stay immutable and are consumed only through their existing compatibility paths; they are never relabelled.

Before the next dispatch, produce fresh 4.4.2 readiness and Role Eval evidence. If no source exists, create exactly one disposable single-CELL Run: place runtime evidence under `slk-conformance/<SLK-CONFORMANCE-…>`, bind Worker to one separate clean, fixed-HEAD, no-remote sample Git while every other role retains its true native workspace/cwd, bootstrap its unique Temporal pair, then explicitly admit it through `ISOLATED_CONFORMANCE_SAMPLE`/`preflight-conformance-sample`; it cannot carry product work. After its real seven legs, seal the source. Product startup uses its own minimal bootstrap, captures native identity, freezes identity-aware RoleHost/OW evidence and a `PRODUCT` config, then runs `preflight-new-run` and `slk-temporal-admit`. An already-running Codex Desktop Overwatcher is preserved in place: the Supervisor records one hash-bound read-only attestation of its exact Run/role/endpoint/thread/turn/platform-input identity, selects standard-adapter v2, and every audit re-reads that exact live turn. This neither replaces the OW nor rewrites prior history. `PAIR_CREATED`, `AWAITING_ADMISSION`, guessed IDs, a custom echo adapter, sample-mode product dispatch or product replay cannot qualify. Freeze OCRV limits, confirm the canonical Checker attempt root, and prove current role endpoints and credential consumers. Supervisor reviews remaining undispatched CELL sizes against actual DSH capability and cumulative load.

The ordinary loop still belongs to Checker and Worker. The first formal product D1 failure may use the bounded same-CELL rework path. A second-or-later formal D1 failure makes the old RoleHost return `ROLE_HOST_CELL_SPLIT_REQUIRED`: Supervisor compares both rounds, consumes sealed `supervisor-admin revise-plan`, freezes a new revision Host, updates the standard Temporal Run config, and returns the first successor through normal `Supervisor → Checker CELL_DISPATCH`. INCOMPLETE, tool/transport failure and duplicate receipts do not count. If no honest split remains, keep the Run blocked rather than dispatching Worker directly or issuing another ordinary retry.

Terminal migration keeps credentials sealed: use `supervisor-admin close-overwatcher` with the exact saved OW credential and final cycle, then `supervisor-admin close-run` for the sole `RUN_CLOSED` event, then `supervisor-admin close-role` for Worker and Checker. Do not decrypt a role credential or substitute an ordinary shell command.

BI/WebBI remain 1.1.0. No Docker installation, extra role, scheduler, daemon, wmux substrate, push, tag or Release is part of this migration.
