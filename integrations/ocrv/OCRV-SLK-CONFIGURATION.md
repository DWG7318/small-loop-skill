# OCRV integration for SLK 4.5.2

OCRV is the registered original Checker, normally Qwen3.8-Max. Worker owns D0, original Checker owns D1, Supervisor owns D2. SLK never derives D1 from severity, finding counts, coverage, task_done, native exit or missing output.

Save and deliver every existing report/log, even partial, non-JSON or nonzero-exit output. Delivery is independent of TOKEN/state/Temporal engineering-dispatch guards; failure is reported as a communication fact. A saved file is not proof of delivery. No format supplement, synthesized terminal, classification correction or automatic review retry is required. Historical reports/FAIL remain unchanged and are not reinterpreted as new explicit decisions.

OCRV 1.12.12/1.12.13 is a stateless review harness. Its built-ins cannot call arbitrary shell commands, and commit/range `file_read` reads Git objects, not uncommitted runtime originals. Reuse its existing stdio MCP bridge for `slk_checker_decide(verdict, message?)` and `slk_read_evidence(index, offset?, limit?)`; no arbitrary path, identity, credentials, shell or general executor is accepted from the model. Identity comes from the prepared host and native invocation receipt. Without a deliberate decision call no D1 is recorded. An action error is not PASS/FAIL and cannot prevent report delivery.

After deployment is independently authorized, the unified offline installer accepts explicit `-OcrvUserHome <native-user-home>`. It merges only the four SLK-owned fields of `mcp_servers.slk_checker_decision` into `<native-user-home>/.opencodereview/config.json`. Omitting that parameter retains the existing code-only contract. The legacy standalone OCRV integration installer remains code-only.

Deployment order (Supervisor only after acceptance): install the hash-bound method package and run its existing `integrations/ocrv/install.ps1 -OcrvRoot <selected OCRV root>`, then merge the MCP entry below. Before any real review, inspect the selected `ocr-slk.ps1` rule argument: Root confirmed this machine currently forces `D:/OCRV/slk/slk-d1-rule.json`, which references old `SLK-D1-REVIEW.md` prose claiming adapter classification. Keep the existing wrapper and rule JSON path. Retain the original config in the existing deployment backup, remove ONLY the `rules` entry referencing that legacy SLK Markdown, and preserve `include` byte-for-byte in meaning (including test files), `exclude` and unrelated configuration. Leave the old Markdown as history, not a loaded override; do not add a second SLK rule file or another wrapper. The generated background is the sole SLK responsibility prose loaded by the native review, with the bound tool description. A source/Skill update alone does not perform this deployment.

After that exact edit, compare before/after config: unchanged inclusion/exclusion and unrelated entries, no remaining legacy SLK prose override. Read back actual wrapper/config paths and installed hashes; run the normal native `--preview` for the unchanged candidate/scope and MCP tool discovery, checking test-file inclusion and the whole-candidate tool description. Preview/discovery is not a paid review or D1 proof. Missing/conflicting rules or tools keep product readiness blocked. Root performs this real-runtime edit and evidence collection after independent acceptance; this maintenance candidate did not inspect, change or dispatch the actual runtime.

```powershell
# Both roots are selected at authorized deployment, never from maintainer PATH.
pwsh -NoProfile -NonInteractive -File <package>/tools/slk/scripts/install_local.ps1 `
    -PackageRoot <package> -CodexHome <selected-codex-home> -OcrvUserHome <selected-native-user-home>
```

The resulting stdio command is `<selected-codex-home>/tools/slk/runtime/python/python.exe`; args are `-B`, its sibling `runtime/ocrv/slk_checker_decision.py`, `--transport`, and `bin/slk-transport.pyz`. Allowed tools are exactly `slk_checker_decide` and `slk_read_evidence`. The non-resident `scripts/configure_ocrv.py` helper preserves every non-owned JSON value, including false/empty arrays and unknown SLK-entry fields. Bad JSON is not overwritten, unchanged configuration is not rewritten, and original bytes are retained in the existing install backup. Failed installation restores only the configuration version it wrote; intervening external edits are retained and reported as a rollback conflict. No accounts or provider/model choices are copied or changed.

Packaged native OCRV uses the actual child's Windows `USERPROFILE` for configuration and Sessions. The same child environment is used for preview/review/Session lookup; legacy wrapper and authoritative explicit command conventions remain unchanged. SLK artifacts default to mutable `tools/slk/data/ocrv`; `OCRV_SLK_RUNTIME_ROOT` remains authoritative. Exact packaged automatic Checker endpoints bypass CMD using embedded Python and the existing adapter script. The public CMD is a limited human convenience, not an arbitrary request/output-path channel.

The exact `--transport` package is placed first on the MCP subprocess import path; a source checkout/PYTHONPATH is not assumed. Stdio uses UTF-8 independently of Windows locale. Optional `message` carries original Checker findings/reasons without a report template. The deliberate tool call persists D1 only. Existing Host completion dispatches the successor after native exit, stream drain, report publication and the matching transport terminal; OCRV needs no shell or second Agent.

The adapter binds a hash-checked evidence index to this exact native invocation. Generated background is a compact bootstrap, not the request or evidence inventory: it does not grow with goal text, criteria, management summaries or evidence counts. Before independent preliminary review, OCRV must read index **0**, the complete unchanged original request (candidate, full goal, every criterion, scope, capacity and optional Supervisor management context), and index **1**, the complete material catalog. The catalog lists engineering originals at indices **2 onward**, including hashes, frozen refs/gaps and capability metadata. Only after its independent initial judgment does OCRV read relevant Worker D0 originals and reconcile them before final D1. The strict request contract projects no Worker D0/report/reasoning bodies into that first request read; those remain separately indexed. The catalog hashes neither itself nor its enclosing index, avoiding a self-reference cycle. A fresh native resume uses its new invocation's catalog numbers, not historical ones; legacy explicit background overrides retain their original numbering.

`slk_read_evidence` accepts only bound numbered files and checks original SHA256 on each read. It returns the full original by default, or the remainder from an optional character offset; OCRV may supply a positive `limit` of any size to select a range. The tool has no content-length ceiling, implicit paging or automatic truncation, including above 8000 characters; `next_offset` and `eof` identify the returned range, and CR/LF are retained. A requested range is not the full original: mandatory request/catalog reads must reach EOF before review. Changed originals/indexes or mismatched invocations are errors, not substitute summaries. Binary/non-UTF-8 originals are not silently decoded. Supervisor management returns preserve the existing candidate/goal/criteria and carry their original summary plus evidence refs into the same request (optional `management_context` in v2); supplied hashes are checked, not recomputed to overwrite the sender's value. OCRV's separate native 8000-cleaned-character / 1 MiB background-file limits and actual model/platform capacity remain unchanged; the full materials are not submitted as background and are not truncated to those limits. Offline gate-aware tests verify material access and the stated read order, not whether a real model obeys it.

The bridge's completion receipt proves the explicit decision was persisted, not that native writers stopped. The adapter never kills a review on D1 or capacity. It waits for natural native exit and both stream drains, then authenticates the receipt and publishes the result before Host completion. Native background compression and comment work are joined before final session sealing. Actual exit and `EXPLICIT_D1_COMPLETED` remain separate facts. Public decision message/path/hash survive an absent raw review; absent findings are `null`, not an invented empty review. Verified native Session headers supply actual provider/model; configured dispatch identity is labeled requested, never guessed as actual. Native exit, findings and action errors cannot manufacture D1. Candidate changes require paired deployment at an authorized boundary and do not modify a running review.

OCRV inherits the invocation-bound environment from the existing transport. Preparation must verify both configured tools are actually discoverable, an indexed Git-external original is readable through this bridge, and local `slk_transport` resolves to the deployed package. No generic command tool or alternative D1 author may replace it. Offline protocol/action/process tests prove wiring, original reads and exact cleanup only, not that the real model consistently makes a whole-candidate decision or calls the tools correctly.

Before a Run, verify version/update need, managed wrapper/capability hashes, headless execution, actual model/endpoint, native activity and available standard actions. Native preview is optional input planning, never a report-release test. Every helper remains headless and ends with its invocation; no daemon is added. A wrapper invocation/launcher PID is not a native Session/Go PID. The background's unique invocation/request-SHA marker is matched only in a native `llm_request` input, cross-checked against header cwd/candidate/provider/model, and bound by immutable header/input-record hashes. Discovery considers only exact-repo files absent before launch (or an explicitly resumed ID); subsequent reads use only the bound Session. The original MCP bridge records its direct native parent's process identity under the exact launcher; this optional observation never gates evidence reading or D1. ACTIVE means that exact native executor is alive, not that progress or handoff occurred. Missing/ambiguous binding or unqueryable native process stays UNKNOWN, retaining any proven last native action. Public `tool_call`/`session_end` metadata is read separately from wrapper stdout/stderr; no messages, arguments, results, reasoning or native payload are published. Original logs can exceed 10MB: only compact observation metadata is persisted, not a copied log or mutable whole-file hash. These are invocation-bound producer/reader changes, not an independent all-tool one-minute/10MB collector. No OCRV archive flag is confirmed; do not infer archive state from BI or filenames.

First formal FAIL goes to Supervisor for bounded guidance. After a second consecutive formal FAIL, Supervisor investigates more aggressively and considers smaller successor CELLs; this is role guidance, not a host verdict/rework veto. Only explicit role actions may advance engineering state or start next work.

Invocation boundary: OCRV groups remain native file reviews; `task_done` and successful reused groups are not whole-CELL D1. The SLK-enabled native patch performs one final whole-CELL judgment after groups/background settle, using the same runner/provider/model/MCP and public group results, frozen criteria and necessary cross-file context. Group conversations cannot invoke the D1 tool. A successful final decision ends that tool loop immediately; remaining background work joins before session finalization. Ordinary non-SLK OCRV is unchanged. Fully reused files still reach this final stage when D1 is absent; partial reuse still relies on the native successful-file checkpoints. An authenticated existing central D1 skips all new model/probe work. Native resume/supplement preflight requires the original parsed endpoint/envelope, bound Host/receipt, unchanged CELL scope and exact Session with its actual closed manifest; interrupted sessions without a manifest are not fabricated into resumable ones. This adds no second Checker, CELL or state engine, and does not guarantee provider availability or model correctness.

Capacity: frozen endpoint `review_capacity` reaches native argv unchanged by default. Only explicit `ADJUST_CAPACITY` with the exact existing policy may set aggregate token budget and per-group timeout to zero; registered `max_tokens` remains model-specific. `--max-tools 0` means the native template default, not unlimited tool rounds. Provider request timeout remains separate. Engineering evidence selection is relevance-based; private native stderr/thinking files stay archived outside the default evidence index, while public indexed originals retain full-EOF reads without arbitrary character caps.

Explicit recovery uses the same installed launcher and existing native `--resume`, not the retired implicit budget/format retries. The registered Supervisor supplies the unchanged prepared Host binding/hash, exact source attempt, verified original native Session ID and one invocation UUID:

```powershell
& <installed-ocrv-integration>/slk-checker.cmd --slk-resume-review `
    --binding <absolute-role-host-binding.json> --sha256 <binding-sha256> `
    --source-attempt <absolute-original-attempt> --resume-session <bound-session-id> `
    --invocation-id <new-canonical-uuid>
```

Preflight authenticates that Supervisor, the registered Checker endpoint/envelope, frozen candidate/capacity, native receipt and exact Session. Both the original launcher and MCP-bound executor must be proved stopped; a D1 or `session_end` alone is insufficient. Missing/unqueryable process proof, absent closed manifest for new model work, changed runtime Session directory or changed scope rejects before any native/probe launch. An already authenticated D1 permits only the original Host handoff suffix, never a new review or manufactured result. If its original seal is missing, preserve D1 and inspect the missing evidence; this command does not reconstruct it.

Without D1, one explicit child is created under `source/review-corrections/<invocation-id>`. Original request/endpoint/envelope bytes and logical D1 message stay unchanged; fresh native receipts/results have their own directory, and the public report gets a provenance-checked delivery ID so it cannot overwrite the original report. Run quiescence includes these exact descendants and checks both writer identities. Repeating the same invocation never launches another model: it reuses a delivered report or retries only its unconfirmed Host suffix. A later native continuation names the last verified child source and its bound Session, never creates a sibling activation. Return code 0 requires authenticated D1 and committed handoff; 3 preserves an incomplete review or pending handoff, and 4 rejects unproved recovery. Native exit 0 alone still cannot create PASS. No automatic retry, daemon or extra state engine is added.

Live Overwatch collection and cycle validation read the same unique, provenance-checked OCRV continuation leaf while retaining the original central message/start SHA. Pending or incomplete claims, changed markers, multiple leaves or unproved stopped writers stay UNKNOWN instead of inheriting the original Session's terminal state. Observation does not unwrap credentials or authorize recovery.
