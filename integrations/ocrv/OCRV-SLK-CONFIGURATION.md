# OCRV integration for SLK 4.4.2

OCRV is the registered original Checker, normally Qwen3.8-Max. Worker owns D0, original Checker owns D1, Supervisor owns D2. SLK never derives D1 from severity, finding counts, coverage, task_done, native exit or missing output.

Save and deliver every existing report/log, even partial, non-JSON or nonzero-exit output. Delivery is independent of TOKEN/state/Temporal engineering-dispatch guards; failure is reported as a communication fact. A saved file is not proof of delivery. No format supplement, synthesized terminal, classification correction or automatic review retry is required. Historical reports/FAIL remain unchanged and are not reinterpreted as new explicit decisions.

OCRV 1.12.12/1.12.13 is a stateless review harness. Its built-ins cannot call arbitrary shell commands, and commit/range `file_read` reads Git objects, not uncommitted runtime originals. Reuse its existing stdio MCP bridge for `slk_checker_decide(verdict, message?)` and `slk_read_evidence(index, offset?, limit?)`; no arbitrary path, identity, credentials, shell or general executor is accepted from the model. Identity comes from the prepared host and native invocation receipt. Without a deliberate decision call no D1 is recorded. An action error is not PASS/FAIL and cannot prevent report delivery.

```powershell
function Get-SlkCheckerMcpConfiguration([string]$OcrvRoot) {
    $python = (Get-Command python.exe -ErrorAction Stop).Source
    $launcher = (Get-Command slk-transport.cmd -ErrorAction Stop).Source
    $package = Join-Path (Split-Path $launcher) 'slk-transport.pyz'
    $bridge = Join-Path ([IO.Path]::GetFullPath($OcrvRoot)) 'slk_checker_decision.py'
    foreach ($path in @($package, $bridge)) {
        if (-not (Test-Path -LiteralPath $path -PathType Leaf)) { throw "Missing installed file: $path" }
    }
    @{slk_checker_decision=@{type='stdio'; command=$python;
        args=@('-B', $bridge, '--transport', $package); tools=@('slk_checker_decide','slk_read_evidence')}} |
        ConvertTo-Json -Depth 5
}
```

The exact `--transport` package is placed first on the MCP subprocess import path; a source checkout/PYTHONPATH is not assumed. Stdio uses UTF-8 independently of Windows locale. Optional `message` carries original Checker findings/reasons without a report template. The one deliberate tool call records D1 and runs the existing standard successor; OCRV needs no shell or second suffix invocation.

The adapter binds a hash-checked evidence index to this exact native invocation. `slk_read_evidence` accepts only its numbered files and checks original SHA256 on each read. It returns the full original by default, or the remainder from an optional character offset; OCRV may supply a positive `limit` of any size to select a range. The tool has no content-length ceiling, implicit paging or automatic truncation, including above 8000 characters; `next_offset` and `eof` identify the returned range, and CR/LF are retained. OCRV chooses how much to read. Changed originals/indexes or mismatched invocations are errors, not substitute summaries. Binary/non-UTF-8 originals are not silently decoded. Background contains locators, never the full log; a requested range is not the full original. Supervisor management returns preserve the existing candidate/goal/criteria and carry their original summary plus evidence refs into the same request (optional `management_context` in v2); supplied hashes are checked, not recomputed to overwrite the sender's value. Removing the reader's limits does not remove OCRV's separate native background-file limit or actual model/platform capacity.

Finish this review's business and save its report/evidence before the final explicit D1/handoff action; do not start another group after handoff. After that action returns and its MCP reply is flushed, the bridge writes a completion receipt bound to the native start and immutable decision. The adapter validates the same receipt whether the original process is still running or has naturally exited. Only a still-running exact owned review is closed after checking OS ancestry and creation time. Do not tree-kill: the action may already have launched a legitimate successor. Existing stdout/stderr and any available partial raw report remain saved; actual native exit code and `EXPLICIT_D1_COMPLETED` are recorded separately. Natural exit, findings or action errors cannot manufacture the receipt or a D1 verdict. This is invocation cleanup, not another role/session, automatic retry or reinterpretation of D1. Candidate code/config changes require paired deployment at an authorized boundary; they do not alter an already running review.

OCRV inherits the invocation-bound environment from the existing transport. Preparation must verify both configured tools are actually discoverable, an indexed Git-external original is readable through this bridge, and local `slk_transport` resolves to the deployed package. No generic command tool or alternative D1 author may replace it. Offline protocol/action/process tests prove wiring, original reads and exact cleanup only, not that the real model consistently makes a whole-candidate decision or calls the tools correctly.

Before a Run, verify version/update need, managed wrapper/capability hashes, headless execution, actual model/endpoint, native activity and available standard actions. Native preview is optional input planning, never a report-release test. Every helper remains headless and ends with its invocation; no daemon is added. A wrapper invocation/launcher PID is not a native Session/Go PID. The background's unique invocation/request-SHA marker is matched only in a native `llm_request` input, cross-checked against header cwd/candidate/provider/model, and bound by immutable header/input-record hashes. Discovery considers only exact-repo files absent before launch (or an explicitly resumed ID); subsequent reads use only the bound Session. The original MCP bridge records its direct native parent's process identity under the exact launcher; this optional observation never gates evidence reading or D1. ACTIVE means that exact native executor is alive, not that progress or handoff occurred. Missing/ambiguous binding or unqueryable native process stays UNKNOWN, retaining any proven last native action. Public `tool_call`/`session_end` metadata is read separately from wrapper stdout/stderr; no messages, arguments, results, reasoning or native payload are published. Original logs can exceed 10MB: only compact observation metadata is persisted, not a copied log or mutable whole-file hash. These are invocation-bound producer/reader changes, not an independent all-tool one-minute/10MB collector. No OCRV archive flag is confirmed; do not infer archive state from BI or filenames.

First formal FAIL goes to Supervisor for bounded guidance. After a second consecutive formal FAIL, Supervisor investigates more aggressively and considers smaller successor CELLs; this is role guidance, not a host verdict/rework veto. Only explicit role actions may advance engineering state or start next work.

Invocation boundary: OCRV may split the selected diff into semantic/per-file groups, each with its own plan/main conversation and the same registered tools. `--concurrency 1` serializes groups; it does not merge them. Native review identity is authority evidence, NOT proof of whole-candidate review. Existing `file_find`/`file_read_diff` permit cross-file inspection; the native diff map is injected before grouping. Background and tool descriptions require one decision for the entire frozen candidate/all CELL criteria, never one per file/group; unverified goals must not become whole-CELL PASS.
