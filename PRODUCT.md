# Product

## Register

product

## Platform

web

## Users

The primary user is the Owner or operator overseeing one or more concurrent SLK Runs on the same computer. Secondary users are read-only Agents that need exact project, Run, GO, CELL, role, TOKEN, evidence, and history facts without entering a role conversation or mutating SLK state.

## Product Purpose

SLK BI makes the durable SLK 4.0 state understandable at a glance. It provides one global view across projects and Runs, then lets the user inspect the current responsibility boundary, serial GO/CELL progress, role identity and session history, plan revisions, events, evidence, corrections, resource contention, and closure facts.

Success means the user can answer "where is this Run, who owns the next action, and what facts support that state?" without asking a role to restate its memory. The BI never substitutes display state for role communication or inspection.

## Positioning

One factual, read-only window onto the same authority used by SLK roles and Agent queries, with no second state model and no control plane hidden in the interface.

## Brand Personality

Calm, exact, and operational. The interface shares LCaS's desktop workbench language: compact system typography, disciplined dark and light themes, restrained blue emphasis, and motion used only to clarify state changes.

## Anti-references

- No command-center spectacle, glowing control room, or decorative telemetry.
- No card-grid dashboard that hides the serial Run structure.
- No confirmation, approval, dispatch, repair, exemption, or state-editing controls.
- No "live" or "working now" claim derived only from an old status record.
- No independent copy of state, credentials, or provider secrets.

## Design Principles

1. Show responsibility before activity: current SLK TOKEN ownership is more important than decorative metrics.
2. Show the linear path: GO and CELL progression must remain visibly serial and understandable.
3. Separate fact from inference: timestamps and authored events are explicit; unproved liveness stays unclaimed.
4. Reveal detail progressively: global overview first, then Run, node, role, event, and evidence detail.
5. Preserve method boundaries: BI reads; Supervisor, Checker, and Worker remain the only writers and decision makers.

## Accessibility & Inclusion

The interface targets WCAG 2.2 AA contrast, complete keyboard navigation, visible focus, semantic status text that does not rely on color, reduced-motion support, and usable light and dark themes. Dense information remains zoom-safe and horizontally resilient at desktop sizes.
